# ADR-0009: Place every regression test as a node:test file under test/<area>/ (Rust story excepted) and verify per story with a targeted command

**Status:** Accepted
**Context:** packages/baro-orchestrator/package.json:15 runs `node --import tsx --test --test-concurrency=2 "test/**/*.test.ts"`, and the existing suite is organised by area (test/verification, test/execution — e.g. test/execution/publish-guard.test.ts, which already exercises a Bash PreToolUse hook denial end to end and is the model for the Claude-lane test). The intake story is Rust and has no place in that tree. Running the whole orchestrator suite as each story's proof is slow and couples the five stories' verdicts to each other.
**Decision:** Test files, one per story:
- STORY-167: packages/baro-orchestrator/test/verification/declared-credit.test.ts — asserts a declared `node --test --import tsx <file>` command is accepted by translation and survives revalidateContainedPaths; 21 declared files collapse to one VerifyCommandSpec and consume one budget unit; a declared file executed green by another command in the same run is credited and produces no incompleteReason.
- STORY-168: packages/baro-orchestrator/test/verification/verify-cwd.test.ts — asserts the merge, cleanup, verify sequence passes with the resolver in place, and that a verification whose resolved cwd was removed yields environment:true rather than a test failure.
- STORY-170: packages/baro-orchestrator/test/verification/failure-classifier.test.ts — one tail per bucket produces the right remedy; an environment tail retries exactly once after remediation; a time-ceiling tail retries at most once; the bucket and remedy appear in VerificationCommandEvidence and in a RunVerificationRetryClassified event.
- STORY-169: packages/baro-orchestrator/test/execution/shell-containment.test.ts — the generated hook source refuses `mktemp -d && git worktree add ...`, allows a command writing only under the worktree, and announceGates(BASE_GATES, ...) contains `[gate:shell-containment]`.
- STORY-165: Rust, in crates/baro-tui, following whichever convention the touched module already uses (inline `#[cfg(test)] mod tests` if the module has one, otherwise crates/baro-tui/tests/): a 12_000-character --goal-file goal starts a run headlessly and carries the truncation note when over the ceiling; an over-limit interactive submission still errors.
Per-story verification command: the four TypeScript stories run `npm run typecheck -w packages/baro-orchestrator` plus `node --import tsx --test <their one test file>`; STORY-165 runs `cargo build` plus `cargo test -p baro-tui`. The full `npm run test` per workspace plus `cargo build` and `cargo test` are the run-level gate after all five merge, not each story's own perimeter.
Every test must be written to fail against the pre-change tree — assert the new behaviour, never merely that the new symbol exists.
**Consequences:** Each story's verdict depends only on files it owns, so the ordered verification chain does not cascade unrelated red. Fixtures that need a worktree or a spawn must use the injection points the code already exposes (VerifyBuildOptions.sleep, resolveRunCwd, BARO_FAILURE_SIGNALS_FILE) rather than real processes or real git where avoidable. STORY-167 is the one story expected to also update pre-existing declared-budget assertions, since it changes what a budget unit means.
