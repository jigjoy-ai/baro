# ADR-0001: Add rejection code `overlapping_write_surface` to the existing RuntimeReplanRejectionCode union

**Status:** Accepted
**Context:** Rejections are a closed string-literal union (src/events/runtime-graph.ts:95-115) surfaced verbatim by the coordinator. A new named code is required by the acceptance criterion; reusing `invalid_proposal` or `duplicate_story` would be unnamed/misleading. The goal explicitly allows keeping the proposed name.
**Decision:** Add the literal `"overlapping_write_surface"` to the `RuntimeReplanRejectionCode` union in packages/baro-orchestrator/src/events/runtime-graph.ts (append after `"duplicate_story"`, keeping the existing one-literal-per-line formatting and any adjacent comment style). Do NOT rename or reorder existing literals, do NOT change RuntimeReplanRejectedData, and do NOT touch src/runtime-graph/runtime-replan-coordinator.ts — it already forwards `validation.code`/`validation.reason` unchanged (210-230). Do NOT touch anything under crates/ or desktop/. If docs/collective-runtime.md enumerates the rejection codes, add the new code to that list in the same story; if it does not enumerate them, change no docs.
**Consequences:** The code reaches the wire and the TUI as a plain string; no exhaustive-match sites need updating in TypeScript. This file is owned by the runtime-replan story (ADR on the write partition) so no other story may edit src/events/runtime-graph.ts.
