# ADR-0005: Make the fragment publish receipt's obligationNote carry concrete unowned ids and add unownedObligationIds

**Status:** Accepted
**Context:** planner-openai-progressive.ts:285-296 tests only whether THIS fragment mentions any `[O-<digits>]`, so `[O-7]` suppresses the note although it names no real obligation, and the note never says which obligations are still open. The receipt is untyped (`Promise<Record<string, unknown>>`, :56) and has no consumer other than the model, which reads it as JSON, so the shape is free to grow — but `hostFeedback` is spread last (:297-307) and would shadow a colliding key.
**Decision:** In packages/baro-orchestrator/src/planning/adapters/planner-openai-progressive.ts replace lines 285-296 with, computed AFTER `session.admit` (:272) so the just-admitted fragment counts: `const unowned = unownedObligationIds(obligationContract, session.snapshot().stories)` and `const totalObligations = obligationContract?.obligations.length ?? 0`. Set `obligationNote` to `undefined` when `totalObligations === 0 || unowned.length === 0`; otherwise to the single string `` `WARNING: ${unowned.length} of ${totalObligations} architecture obligation(s) are still unowned after this fragment: ${formatObligationIdList(unowned)}. Published stories are immutable — an obligation not attached at publish time can never be attached, and planning closes incomplete.` ``. Keep the receipt literal's existing keys and their order (`ok`, `disposition`, `fragmentId`, `ordinal`, `fingerprint`, `storyIds`, `nextOrdinal`), keep `...(obligationNote ? { obligationNote } : {})`, and add immediately after it `...(unowned.length > 0 ? { unownedObligationIds: [...unowned] } : {})`, still before the `...(hostFeedback ?? {})` spread. Keep the key name `obligationNote` — do not rename it and do not introduce a second note key. Delete the local `fragmentOwnsObligations` presence test and its regex entirely. Do NOT move or change the `"partial"`-mode `validateArchitectureObligationCoverage` call at :257-271, and do NOT let any of this block admission — the note is still computed after `config.publish(event)` and never throws.
**Consequences:** The model now sees the running gap and the exact ids at each publish, while ownership semantics and admission are unchanged. `unownedObligationIds` is a new receipt key the model may read; because `hostFeedback` still spreads last, a host feedback key of the same name would win, which is acceptable and unchanged in kind from the existing `obligationNote` hazard. Tests must assert ids, not the presence of the word WARNING.
