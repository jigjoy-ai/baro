# ADR-0005: Split into three stories with disjoint writes and per-story verification

**Status:** Accepted
**Context:** The run constraints require exact non-overlapping `writes` arrays and per-perimeter verification; the touched surfaces fall cleanly into a Rust half and two TypeScript halves, except that the writer file is edited by both the wiring and the reporting change and must not be split across parallel agents.
**Decision:** Three stories.
Story A (parallel, Rust): writes = ["crates/baro-tui/src/main.rs"]. Tests = `cargo test -p baro-tui goal_fingerprint`.
Story B (parallel with A, TypeScript): writes = ["packages/baro-orchestrator/src/orchestrate.ts", "packages/baro-orchestrator/src/execution/prd-status-writer.ts", "<existing prd-status-writer test file under packages/baro-orchestrator/test/>"]. Implements the wiring ADR and the activity-event ADR together. Tests = the path-filtered runner invocation for that one test file.
Story C (after B): writes = ["packages/baro-orchestrator/test/execution/prd-status-resume-loop.test.ts"]. Tests = the path-filtered runner invocation for that one file.
No story edits crates/baro-tui/src/cli/*, selectResumeStories or its module, test/execution/resume-selection.test.ts, git-coordinator.ts, local-repository-agent.ts, conductor.ts, or prd.ts. No story runs a repo-wide suite. The PR description (owned by the run, drafted from Story B's findings) must carry the root-cause statement with citations and the ruled-out alternatives.
**Consequences:** A and B run in parallel with no shared files; C serializes behind B because it asserts B's behaviour. If a targeted test flakes under load, rerun that single test in isolation once and let the isolated result stand.
