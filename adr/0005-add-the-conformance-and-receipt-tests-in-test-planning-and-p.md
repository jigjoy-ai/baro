# ADR-0005: Add the conformance and receipt tests in test/planning/ and prove ordering through production builders only

**Status:** Accepted
**Context:** The goal requires a test proving at least one coverage-gap notice precedes the terminal 'global goal is not satisfied … open invariant(s)' failure. The two strings are produced by different layers: the notice by plan-events.ts:52-57 / the publisher's sink, the terminal reason by VerificationGoalGate.onGoalCompletionAttested (verification-goal-gate.ts:341-350) which hands it to `host.requestPush`. Stubbing process.stdout to read the NDJSON feed is fragile; injecting sinks is already the repository's shape.
**Decision:** Add ONE new file: packages/baro-orchestrator/test/planning/planner-invariant-coverage-conformance.test.ts, using the same runner, import style and fixture-construction helpers as packages/baro-orchestrator/test/planning/planner-progressive-invariant-note.test.ts. Do not modify the three existing #116 test files except to add cases if a shared fixture is exported from them.
It contains exactly three tests:
1. `bus-session receipt carries unowned invariant ids` — drive the claude lane through `createPlannerHarnessProgressiveSupport` as planner-bus-session.ts:352-389 configures it (host `publish` returning only `{graphVersion, admittedStoryIds, replayed}`), publish one fragment whose stories set `goalInvariantIds: []`, parse the returned JSON receipt, assert `receipt.unownedInvariantIds` deep-equals every contract invariant id and `receipt.invariantNote` starts with `WARNING:` and contains the same ids.
2. `repair prompt lists invariant ids with canonical statements` — call `buildFinalPrdRepairMessage` with `unownedInvariants` from `unownedInvariantsWithText`, assert the output contains `Unowned goal invariants (2):` and the exact line `- [<id>] <text>` for each, and still contains the untouched obligations line.
3. `coverage notice precedes terminal failure` — build one ordered `string[] observed`. Push `coverage-gap:<ids>` from an injected `onInvariantCoverageGap` sink during the fragment publish of test 1's setup (fragments claim no invariant). Then invoke the real terminal path — `VerificationGoalGate.onGoalCompletionAttested` with an attestation whose `openInvariantIds` are those ids and whose `reason` is produced the same way GoalLedger.assess produces it — with a stub host whose `requestPush(reason)` pushes `terminal:${reason}`. Assert: `observed.findIndex(t => t.startsWith("coverage-gap:"))` is >= 0 and strictly less than `observed.findIndex(t => t.startsWith("terminal:"))`, and that the terminal entry matches `/global goal is not satisfied/` and `/open invariant\(s\)/`. The terminal string MUST come from the production builder, never a literal typed in the test. If VerificationGoalGate cannot be constructed with a stub host, fall back to the run-level harness style of packages/baro-orchestrator/test/execution/collective-board.test.ts and assert the same two indices on its recorded event order — but do not weaken the assertion to 'the notice exists'.
**Consequences:** The ordering proof depends on injected sinks, so it stays stable if the stdout NDJSON format changes. Test 1 is also the characterization test for the first ADR: if it passes before any production edit, the claude lane was already conformant and no adapter change ships.
