# ADR-0009: --resume skips intake/architect/planning and only runs unfinished stories; warn and fall back when the PRD carries no statuses

**Status:** Accepted
**Context:** Rust already short-circuits intake/architect on resume via entered_resume (main.rs:1234, 1242-1255) and never reaches spawn_planner, but the TS side has no resume concept at all (scripts/cli.ts knows only --continue, cli.ts:192-194, 800), so a resumed run re-executes already merged stories.
**Decision:** Rust (S5): when `cli.resume` is true, or the bare-launch decision selects Resume (ADR-011), orchestrator_client build_command pushes `--resume`; OrchestratorConfig gains `resume: bool`. Rust also keeps its existing resume path and must NOT call spawn_planner on that path.
TS: scripts/cli.ts adds `case "--resume": args.resume = true` (declared and defaulted alongside continueRun at cli.ts:64/102) and passes `resumeRun: args.resume || process.env.BARO_RESUME === "1"` into the orchestrator config; orchestrate.ts must, when resumeRun is true, skip intake/architect/planning entirely and load the plan from the PRD as-is.
New src/execution/resume-selection.ts exports pure `selectResumeStories(prd)` -> `{ mode: "statuses" | "legacy", skipped: string[], remaining: PrdStory[], warning?: string }`. A story is skipped iff `story.passes === true || story.mergeStatus === "merged"`. If no story in the PRD has `passes === true` or a defined `mergeStatus`, return mode "legacy" with remaining = all stories and warning exactly `prd.json carries no per-story status; resuming with legacy behavior (all stories will be executed)`; orchestrate.ts prints that warning once. resumeRun and continueRun are independent booleans; when both are set, resume wins for phase skipping and continue keeps its branch-rewrite behavior (orchestrate.ts:672-685).
Tests in test/execution/resume-selection.test.ts cover: statuses present (merged skipped, failed re-run), passes-only legacy PRD, empty PRD, warning text.
**Consequences:** Resume never re-plans, by construction. Stories with `mergeStatus: "failed"` are retried on resume. TS resume relies on prd.json statuses written by ADR-008, so a run started before this change resumes in legacy mode with the warning.
