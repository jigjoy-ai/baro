# ADR-0004: Prove the merged-to-resume loop with a new observer-level integration test over a real on-disk prd.json

**Status:** Accepted
**Context:** The acceptance criterion demands a real test, not reasoning. A full orchestrate() fixture is disproportionate (git coordinator, participants, run lifecycle). The narrowest seam that still exercises the actual wiring is PrdStatusObserver + the real createPrdStatusWriter (real loadPrd/savePrdAtomic, no stubs) over a temp-dir prd.json, then selectResumeStories on the reloaded file. Existing seams exist at the prd-status-writer test and test/execution/resume-selection.test.ts, but neither joins the two halves; composing them in one file is the proof.
**Decision:** Add one new file, packages/baro-orchestrator/test/execution/prd-status-resume-loop.test.ts, and change no other file. Test body:
1. Create a temp dir; write a prd.json containing at least two userStories (ids "S1", "S2") with no mergeStatus, using the package's real save path (savePrdAtomic from src/prd.ts) so the on-disk shape is production-accurate.
2. Construct `createPrdStatusWriter({ prdPath })` with default load/save and an injected `emitActivity` collector; wrap it in `new PrdStatusObserver(writer)` WITHOUT calling setRepositoryAuthority (this is the previously broken authority-less run shape).
3. Deliver `StoryMerged.create({ storyId: "S1", mode: "worktree", mergeCommitSha: "abc1234" , ...})` from an arbitrary participant through the observer's external-event entry point, matching how the existing prd-status-writer test delivers events.
4. Assert on the file re-read from disk (JSON.parse of fs.readFileSync, not the in-memory object): the S1 entry has `mergeStatus === "merged"`, `mergeCommitSha === "abc1234"`, `passes === true`, a non-empty `completedAt`; S2 has no mergeStatus. Assert the collector received zero events.
5. Call `loadPrd(prdPath)` and pass it to `selectResumeStories` exactly as test/execution/resume-selection.test.ts does; assert S1 is absent from the returned stories and S2 is present. Do NOT modify selectResumeStories or its test file.
Run this file path-filtered with the same runner invocation the repo already uses for test/execution/resume-selection.test.ts; no repo-wide suite command.
**Consequences:** Gives one executable end-to-end proof of the loop and guards against re-introducing the authority gate. It depends on the wiring ADR's authority-less acceptance, so it must be sequenced after that story. This story's writes are exactly the one new test file, disjoint from every other story. The PR description must state that the proof is composed at the observer seam rather than through orchestrate().
