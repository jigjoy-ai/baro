# ADR-0004: Implement --detach as spawn-with-redirect, run id `run-<child-pid>`, log at ~/.baro/logs/<run-id>.log

**Status:** Accepted
**Context:** RunRecord.id is `run-{pid}` (run_registry.rs:85,96), so the id is not known until the child exists, yet stdout must be redirected at spawn time. Registry writes are plain fs::write with no locking; a rename after spawn keeps ids consistent without changing the id scheme.
**Decision:** cli.rs (S1): `pub detach: bool` with `#[arg(long)]`, doc `Run in the background and print the run id immediately`.
run_registry.rs (S2): RunRecord gains `#[serde(default)] pub log_path: Option<String>` (field 7); add `pub fn logs_dir() -> Option<PathBuf>` returning `$HOME/.baro/logs` (USERPROFILE fallback, create_dir_all), `pub fn log_path_for(id: &str) -> Option<PathBuf>` = logs_dir()/`{id}.log`, and `pub fn register_detached(goal: &str, cwd: &str, child_pid: u32, log_path: &Path) -> Option<RunHandle>` writing the record with id `run-{child_pid}` and log_path set. Existing `register` keeps writing `log_path: None`. Inline test: round-trip a RunRecord with and without log_path (missing field defaults to None).
launch.rs (S3), pure: `pub struct DetachPlan { pub pending_log: PathBuf, pub final_log: PathBuf, pub caffeinate: Option<Vec<String>> }` and `pub fn plan_detach(logs_dir: &Path, parent_pid: u32, nanos: u128, child_pid: Option<u32>, is_macos: bool, caffeinate_binary_exists: bool) -> DetachPlan`, where pending_log = logs_dir/`.pending-{parent_pid}-{nanos}.log`, final_log = logs_dir/`run-{child_pid}.log` when child_pid is Some, and caffeinate = Some(vec!["caffeinate","-i","-w",child_pid]) only when is_macos && caffeinate_binary_exists && child_pid.is_some(); else None. Unit tests cover all four combinations.
main.rs (S5): when cli.detach, re-exec the same binary (std::env::current_exe) with the original argv minus `--detach`, plus env `BARO_DETACHED=1`; stdout+stderr both redirected to the pending log file (File::create), stdin null, detached process group (reuse subprocess::configure_process_tree); after spawn, rename pending_log -> final_log, call register_detached, spawn caffeinate per the plan (ignore failure), print the run id on one line to stdout (`<run-id>`), and exit 0. The parent must NOT hold a RunHandle (no Drop unregister). --detach is accepted together with every other flag including --resume and --continue; the child re-exec carries them unchanged.
**Consequences:** The detached child, seeing BARO_DETACHED=1, must force headless streaming output (no TUI) — S5 sets cli.headless = true in that case. Renaming while the child holds the fd is safe on unix; on non-unix the rename may fail, in which case the log path recorded is pending_log. Real detached spawns are not covered by tests: only plan_detach and register_detached are; the PR description must state this integration gap.
