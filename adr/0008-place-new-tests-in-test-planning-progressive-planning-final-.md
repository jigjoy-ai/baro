# ADR-0008: Place new tests in `test/planning/progressive-planning-final-tail.test.ts` and scope commands to changed files

**Status:** Accepted
**Context:** ADR-0013 in `adr/` fixes test placement and per-story verification commands; repository-wide suite commands are rejected by the shell, and the run-level gate proves the merged tree.
**Decision:** Add tests in a new file `packages/baro-orchestrator/test/planning/progressive-planning-final-tail.test.ts`. Locate the existing progressive-planning coordinator test file (glob `packages/baro-orchestrator/test/**/*progressive-planning*`) and reuse its fake-host/board builder by importing it or by copying its factory into the new file — do not invent a second host stub shape. Required cases: (1) rejected tail, all admitted stories settled and all obligations/goal invariants owned -> planning closes `completed`, `FinalTailDiscarded` emitted with the tail story ids and the board reason, warn activity emitted; (2) rejected tail whose stories carry an obligation no admitted story owns -> planning closes `failed` with `terminalReason` containing both the board code and reason; (3) `PlanFragmentRejected` observed in both cases; (4) replayed tail -> `completed`, no discard event; (5) direct unit tests of `evaluateFinalTailTolerance` for each `blocker` value. Declared verification commands are the single-file form of the runner already configured in `packages/baro-orchestrator/package.json` `scripts.test`, applied only to the new file and the existing progressive-planning coordinator test file; no repository-wide invocation, no `cargo` command in any story.
**Consequences:** Story perimeters stay targeted. If a targeted test fails under machine load, it is rerun once in isolation and the isolated pass is authoritative.
