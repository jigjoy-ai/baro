# ADR-0006: Test the interception as inline unit tests in usage.rs plus one ordering test in main.rs

**Status:** Accepted
**Context:** run_connect and run_login terminate in `std::process::exit` (main.rs:652, :799) and run_watch/run_logs are invoked with `process::exit` at the call site, so no test can call a side-effect path and observe a return. The crate has no lib target, so an integration `tests/` dir cannot reach these items (Cargo.toml:6-8). The established pattern is inline `#[cfg(test)] mod tests` (main.rs:4437, cli/cli.rs:326) reaching private items via `super::`/`crate::`.
**Decision:** Add `#[cfg(test)] mod tests` at the end of `crates/baro-tui/src/cli/usage.rs` covering, one `#[test]` fn each: (a) `pre_clap_response("login", &["--help".into()])` and `("connect", ["--help"])` each return `Help` with non-empty text containing `Usage: baro login` / `Usage: baro connect`; (b) CONNECT_USAGE contains every flag string listed in the connect ADR and exactly one `Example:`; (c) `("stop", ["r-1", "--help"])` and `("logs", ["r-1", "--help"])` and `("watch", ["r-1", "-h"])` and `("runs", ["-h"])` all return `Help`; (d) `--version` on each of the six returns `Version`, and `VERSION_LINE` equals `format!("baro {}", env!("CARGO_PKG_VERSION"))`; (e) `("logs", ["r-1", "--follow"])` and `("connect", ["--token", "t"])` return `None` so normal dispatch is unaffected; (f) `("plan", ["--help"])` returns `None` so clap still owns unknown words; (g) `AFTER_HELP` contains each of the six summary lines. Add to the existing `#[cfg(test)] mod tests` in main.rs (around :4437) one test asserting `crate::cli::cli::Cli::command().render_long_help().to_string().contains(crate::cli::usage::AFTER_HELP)`-style consistency if the full epilogue is not re-wrapped, otherwise assert containment of each summary line. The 'no side effect' criterion is discharged structurally by the single interception point in ADR-002 — do NOT spawn subprocesses, mock the network, or add a test harness dependency.
**Consequences:** Tests run under plain `cargo test -p baro-tui`; no new dev-dependency. If a future change moves the interception block below a dispatch branch, the ordering guarantee is lost silently, so the interception block must stay the first statement after `raw_args` is collected and carry a one-line comment saying why.
