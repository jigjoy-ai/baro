# ADR-0004: Fix the exact rejection reason strings for workspace-scoped declarations

**Status:** Accepted
**Context:** incomplete() hashes the reason into declaredRequirementKey (:190-224) and verify.ts surfaces it as the skipped command tail, so reason wording is a contract, and the house style is all-lowercase, no trailing period, single-quoted interpolations.
**Decision:** Use these strings verbatim, nothing else: missing/dash-prefixed value → `workspace selector requires a name`; second selector → `package tests accept at most one workspace selector`; selector at/after '--' → `workspace selector must appear before '--'`; root manifest missing or has no workspaces field → `workspace selector requires a 'workspaces' field in the root package.json`; unresolvable name with candidates → `unknown workspace '${name}': known workspaces are ${candidates.join(", ")}`; unresolvable name with no candidates → `unknown workspace '${name}': no workspace packages were resolved`; workspace package.json missing/invalid → `declared package test requires a valid package.json in workspace '${name}'`; script absent from the workspace manifest → `workspace '${name}' package.json does not declare script '${script}'`. For an untrusted script reuse the EXISTING string unchanged: `custom package script '${script}' is not trusted by the baseline verifier policy`. Every existing reason string in translatePackage stays byte-identical, including `root package-manager authority could not be resolved safely`, which remains the message for the no-selector path only.
**Consequences:** declaredRequirementKey values for existing root-scoped declarations are unchanged; new reasons produce new stable keys. Tests assert reasons with toBe/strict equality or an anchored regex, not loose substring guesses.
