# ADR-0002: #167: stop treating runner flags as paths, count invocations, and credit files an executed suite ran

**Status:** Accepted
**Context:** containedPath (declared-verification.ts:1055) rejects every token starting with "-" (:1060-1067), so a declared `node --test --import tsx <file>` is refused before it can run. boundedDeclaredCommands (verify.ts:775) counts admitted commands, but the declared-translation cap (verify.ts:71, :839-858) and per-file admission make 21 declared files look like many units even though coalesceNodeTestScripts (node-test-script.ts:90) can already merge them into one invocation. Nothing today credits a declared file that a suite already executed green, so it is reported as incomplete.
**Decision:** In declared-verification.ts add a per-runner allowlist `RUNNER_FLAGS: Readonly<Record<string, readonly string[]>>` containing at least node: ["--import", "--test", "--test-concurrency", "--test-reporter", "--test-name-pattern"]. A token matching an allowlisted flag for the current runner (bare form and `<flag>=<value>` form; the `=` value of --import/--test-reporter is a module specifier, not a contained path) is classified as a flag and skipped by containedPath/safeFocusedArg instead of rejecting the command. Flags not on the runner's allowlist keep today's rejection. revalidateContainedPaths (:1380) applies the identical classification so the pre-spawn re-check agrees with translation.
Make dedup precede budgeting: in createVerifyPlan, run coalesceNodeTestScripts (and the existing compactCanonicalRstestCommands path) over the translated declared commands BEFORE boundedDeclaredCommands, so `budget.effectiveLimit` counts spawned invocations. Raise nothing: 21 declared node test files must collapse to one spec and consume one unit.
New file src/verification/declared-credit.ts is the single owner of crediting, exporting:
  export interface CreditedRequirement { file: string; creditedBy: string }
  export function creditDeclaredRequirements(requirements: readonly DeclaredTestRequirement[], executed: readonly VerifyCommandResult[]): { credited: readonly CreditedRequirement[]; uncovered: readonly DeclaredTestRequirement[] }
A requirement is credited when some command with status "passed" in this same verification either names the file in its argv or is a whole-suite script whose cwd is an ancestor of the file. verifyBuild calls it after the command loop; credited requirements are recorded as credited, never skipped. `incompleteReason` is emitted only for a requirement left in `uncovered` — i.e. nothing executed it.
**Consequences:** The declared budget semantics change from files to invocations; declared-test-budget.ts doc comments and DeclaredBudgetEvidence text must say "invocations". Existing tests asserting a per-file count will need updating in the same story. The allowlist is data in declared-verification.ts, not a new file, so it ships through tsc.
