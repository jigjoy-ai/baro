# ADR-0006: Thread the host checkout root into verification as an explicit hostRepoRoot option

**Status:** Accepted
**Context:** verifyBuild only knows the run cwd (integrationRoot), but CARGO_TARGET_DIR must be derived from the host checkout, which is `config.cwd`/`repoRoot` (orchestrate.ts:213,595). Deriving it by walking up from __run is impossible — __run lives under tmpdir().
**Decision:** Add an optional `hostRepoRoot?: string` field to the options object of `verifyBuild` in src/verification/verify.ts:1248 (same options bag that carries `refreshDependencies` and `signal`); inside verifyBuild compute `const hostRepoRoot = options.hostRepoRoot ?? cwd` once and pass it to `runCmd` as an extra parameter. Add a required `hostRepoRoot: string` to `RunVerifierOptions` (src/verification/run-verifier.ts:23) and to `FinalizerOptions` (src/integration/finalizer.ts:64), and an optional `hostRepoRoot?: string` to the continuous gate runner options (src/verification/continuous-gate-runner.ts). Every construction site in src/orchestrate.ts sets `hostRepoRoot: repoRoot`; forward it at finalizer.ts:505, run-verifier.ts:52-57,129 and continuous-gate-runner.ts:175-182. Do NOT add a `findRepoRoot`/`git rev-parse --show-toplevel` helper.
**Consequences:** Making the field required on RunVerifierOptions and FinalizerOptions means every existing constructor call and test fixture for those two must be updated; tests are not typechecked (tsconfig include:["src"]), so agents must grep test/ for these constructors rather than rely on tsc.
