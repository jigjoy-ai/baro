# ADR-0002: Inject the awake clock as an optional options-bag field defaulting to the shared singleton

**Status:** Accepted
**Context:** The goal requires the primitive to be fakeable in the style of the `ExecFileCliTimers` seam. That seam is an optional field on an existing options bag with a `??` default resolved once (exec-file-cli.ts:72-73,155), never a positional argument. Adding a required parameter anywhere would break the existing callers the acceptance criteria require to stay green.
**Decision:** Every adopting entry point gains `awakeClock?: AwakeClock` as an optional field on its existing options object (or, where a function has no options bag, a trailing optional parameter `awakeClock: AwakeClock = sharedAwakeClock()`), resolved exactly once at the top of the function body as `const clock = options.awakeClock ?? sharedAwakeClock()`. Do NOT change `ExecFileCliTimers` (exec-file-cli.ts:34-37) — its two members and both existing test fakes (`RecordingClock`, `ManualClock`) stay byte-identical; exec-file-cli takes the clock through a separate new `awakeClock?` field on `ExecFileCliOptions`. Do NOT add a clock to `NamedTimers`. Do NOT thread the clock through constructors as a required argument. Module-private helpers that today take a bare deadline (`retryFitsInPhase(deadlineAt)` at architect-openai.ts:518, `assertArchitectPhaseDeadline(timeoutMs, deadlineAt)` at :523) gain a trailing required `clock: AwakeClock` parameter, since both call sites are in-file (:346, :354).
**Consequences:** No existing caller anywhere in src needs editing to compile. Tests inject by passing `awakeClock: createFakeAwakeClock()`. Production code must never call `Date.now()` directly in an adopted budget path again — reviewers can grep for `Date.now()` in the adopted files as the check.
