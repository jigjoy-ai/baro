# ADR-0005: Emit the phpunit tool as the resolved absolute path, not the relative token

**Status:** Accepted
**Context:** execFileCli spawns through cross-spawn with no shell; resolveCommand does which.sync against PATH after a best-effort process.chdir(options.cwd) (node_modules/cross-spawn/lib/util/resolveCommand.js:16-42). When chdir is unavailable (worker threads) a relative tool path resolves against the parent process cwd, which would silently execute the wrong binary or ENOENT. exec-file-cli.ts itself performs no path resolution. The repo already spawns an absolute target where correctness demands it (planner-harness-progressive.ts:179-185).
**Decision:** The phpunit spec's `tool` is the absolute path returned by containedPath(cwd, "vendor/bin/phpunit", true) — never the literal "vendor/bin/phpunit". The same absolute value is the first containedPaths entry. `label` keeps the declared relative form so evidence stays readable. Do NOT change exec-file-cli.ts, and do NOT add a which/PATH probe. Record this finding — cross-spawn resolves relative commands via PATH plus a best-effort chdir, therefore contained binaries must be spawned absolute — verbatim in the PR description.
**Consequences:** phpunit specs are cwd-independent and worker-thread safe. verifyCommandIdentity keys include the absolute tool, so two temp-dir runs never collide. Test assertions must compare tool against join(dir, "vendor", "bin", "phpunit") (allowing for realpath normalisation on macOS /var → /private/var; assert with the same normalisation the existing contained-path tests use).
