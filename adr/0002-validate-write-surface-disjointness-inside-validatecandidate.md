# ADR-0002: Validate write-surface disjointness inside validateCandidateGraph, on the candidate PRD

**Status:** Accepted
**Context:** The check must run on the post-mutation graph but before the mutation is returned/applied. The candidate PRD exists at runtime-replan.ts:212-223 and is unused until 225; removals are already filtered out of it, which gives the required 'removed in the same mutation is allowed' behaviour for free. Doing the check in the coordinator would bypass the pure validator and its tests.
**Decision:** In packages/baro-orchestrator/src/runtime/runtime-replan.ts, extend `validateCandidateGraph(current, candidate)` (312-409) with a new gate placed AFTER the dependency-cycle check (ends 349) and BEFORE the goal-contract/obligation checks (351-401). To see which stories are new, change `validateCandidateGraph`'s signature to `validateCandidateGraph(current: PrdFile, candidate: PrdFile, addedStoryIds: readonly string[])` and pass the already-derived added-id list from the call at line 225; update no other callers unless the compiler requires it. Implement the comparison in a module-private helper in the same file, `findWriteSurfaceOverlap(candidate, addedStoryIds): { addedStoryId: string; ownerStoryId: string; paths: string[] } | undefined`. Semantics, exhaustively:
- Owner set = `candidate.userStories` entries whose id is NOT in `addedStoryIds` AND whose `passes !== true`. Stories removed in this mutation are already absent from `candidate.userStories`; do not re-filter them.
- Subject set = `candidate.userStories` entries whose id IS in `addedStoryIds`, iterated in `addedStoryIds` order.
- Path sets come from `writeSurfaceOf(story)` imported from the planning domain module (packages/baro-orchestrator/src/planning/domain/dependency-evidence.ts), using the import spelling already used by the other relative imports at the top of runtime-replan.ts. Do NOT re-implement trimming/`./`/leading-`/` stripping and do NOT add a new shared module.
- Overlap = exact equality of normalized path strings. No directory-prefix or glob containment.
- Report the FIRST conflicting (subject, owner) pair in the iteration order above (owners scanned in `candidate.userStories` order), with `paths` = the shared normalized paths sorted with `.sort()`.
- Added-vs-added comparison is explicitly OUT of scope for this change; do not implement it.
On a hit return `reject("overlapping_write_surface", reason)` using the existing local `reject` helper (574-579).
**Consequences:** Fixtures whose stories declare no `writes` are unaffected (empty surfaces never overlap), so existing green replan tests keep passing. Overlap with a `passes === true` story and overlap with a story removed in the same mutation both remain accepted, as required. The gate is pure and all-or-nothing like every neighbouring gate; no persistence or event code changes.
