# ADR-0006: Place tests in the two existing files and verify per file

**Status:** Accepted
**Context:** adr/0013 fixes the mirror layout `test/<area>/<name>.test.ts` and forbids `npm test -w packages/baro-orchestrator`; both target areas already have a home file, and the source-text structural pin at progressive-planning-final-tail.test.ts:177-206 means new coordinator behaviour belongs in that same file.
**Decision:** No new test files. Add cases to:
- packages/baro-orchestrator/test/runtime-graph/runtime-replan-board.test.ts — assert the frozen reason at :932-937 is still byte-identical, and assert the new `result.overlap` facts: `candidateStoryId`, `owners[].storyId`/`ownedFiles`/`collidingPaths`, and `remainingPaths` (including the empty-`remainingPaths` case and a multi-owner case).
- packages/baro-orchestrator/test/planning/progressive-planning-final-tail.test.ts — (a) update the evaluator call count at :106 from 1 to 2; (b) a case where the first evaluation reports `unsettled_stories` and the second, on a board where the story has settled, is tolerated: assert the run closes `completed`, one `warn` activity, `FinalTailDiscarded` emitted, and no `terminalReason`; (c) a case where a genuinely uncovered obligation fails both evaluations: assert `blocker === "obligation_unowned"` and that the terminal reason still matches `/^final_tail_rejected: /` and `/no story owns: /`; (d) assert the terminal reason never contains the id of a story that is settled in the fresh snapshot.
- packages/baro-orchestrator/test/architect-outcome.test.ts is NOT touched; add the `buildWriteSurfaceOverlapRemedySection` assertions (owner line shape, the three numbered remedies, the empty-`remainingPaths` wording, and insertion position between `Defects (` and `Unowned architecture obligations (` inside `buildFinalPrdRepairMessage`) to the existing planner-prompts test file that already covers `buildFinalPrdRepairMessage`; if none exists, create packages/baro-orchestrator/test/planning/planner-prompts-repair.test.ts.
Verification, from the repo root, one command per changed test file: `node --import tsx --test packages/baro-orchestrator/test/<path>.test.ts`, plus `npm run -w packages/baro-orchestrator typecheck` (types change in this run). Never `npm test`, `npm run test:fast`, `npm run test:slow`, `npm install`, or any cargo command. A targeted command failing under load is re-run once in isolation; the isolated result is authoritative. The PR body must contain `Fixes #104`. Comments stay lean per CLAUDE.md — no section banners, no narration.
**Consequences:** Test discovery needs no config change (`.test.ts` suffix already matched by package.json:15 and scripts/test-lanes.mjs:37). Only one assertion in the existing suite is intentionally revised (the call count at :106); every other pinned string must still pass unchanged, which is the run's own regression check.
