# ADR-0008: TypeScript owns per-story prd.json status writes; add mergeStatus and mergeCommitSha

**Status:** Accepted
**Context:** Requirement B6 forces a single transactional owner. Rust only ever rewrites prd.json before spawning the orchestrator (executor.rs:342-356 call sites all precede spawn_executor) and holds no story lifecycle state during the run; TS already owns markStoryPassed (prd.ts:768-786) and savePrdAtomic (prd.ts:217-229) and is the only process observing StoryMerged/StoryMergeFailed. Splitting ownership would mean two writers of one file with no lock.
**Decision:** TS is the sole writer of story status during a run; Rust must not write prd.json between spawn and orchestrator exit.
prd.ts: PrdStory gains `mergeStatus?: "merged" | "failed"` and `mergeCommitSha?: string`; both added to PRD_STORY_FIELDS (prd.ts:59-74) so the exhaustiveness check passes; normalizePrd leaves them untouched when absent.
events/integration.ts: StoryMerged payload gains optional `mergeCommitSha?: string`; StoryMergeFailed is unchanged.
git-coordinator.ts: after a successful mergeBack in both the worktree path (:439-441) and the shared-tree path (:463-465), call getHeadSha(<run branch cwd>) (integration/git.ts:121) and pass it as mergeCommitSha; on failure to read the sha, emit without the field. local-repository-agent.ts:48-56 emits without the field.
New src/execution/prd-status-writer.ts exports `createPrdStatusWriter({ prdPath, load = loadPrd, save = savePrdAtomic, warn })` returning `{ onStoryMerged(storyId, mergeCommitSha?), onStoryFailed(storyId) }`. Each call re-loads the PRD from disk, applies the mutation (merged: `passes: true`, `completedAt: new Date().toISOString()`, `mergeStatus: "merged"`, `mergeCommitSha` when defined; failed: `mergeStatus: "failed"`, `passes` untouched), and writes with savePrdAtomic. Unknown storyId is a no-op plus one warn line. Write errors are caught, warned once per story, and never throw into the event bus.
orchestrate.ts subscribes the writer to StoryMerged and StoryMergeFailed (and to the terminal StoryResult failure settlement path already wired at orchestrate.ts:1243-1246 for onStoryFailed).
Tests in test/execution/prd-status-writer.test.ts (node:test) drive the writer with the existing StoryMerged/StoryMergeFailed event fixtures over a temp prd.json and assert on-disk content after each event.
**Consequences:** prd.json is rewritten once per merge/failure; because every write is load-modify-savePrdAtomic and only one process writes during a run, no lock is needed. Rust must round-trip the two new fields (ADR-011 story S4) or they will be dropped on the next Rust rewrite. mergeCommitSha is best-effort: absent when getHeadSha fails or on the no-git local path.
