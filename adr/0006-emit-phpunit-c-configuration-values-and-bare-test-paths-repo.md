# ADR-0006: Emit phpunit -c/--configuration values and bare test paths repo-relative while keeping TOOL host-absolute and containedPaths absolute

**Status:** Accepted
**Context:** translatePhpunit absolutizes the config value (:928-929) and test paths (:942-944); translateDdev emits args ["exec", innerTokens[0]!, ...inner.args] (:1004), so those absolute host paths leak into the container argv. TOOL must stay absolute because cross-spawn resolves relative commands through PATH (comment :952-954). containedPaths may be absolute or relative but must be internally consistent; revalidateContainedPaths already re-relativizes absolute entries (:1022-1024).
**Decision:** In translatePhpunit: push `contained.path` (repo-relative, forward slashes, as returned by containedPath) into `args` for both the -c/--configuration value and bare test paths — drop the join(cwd, …) at those two sites only. Keep `tool: join(cwd, binary.path)` host-absolute. Keep ALL containedPaths entries ABSOLUTE (binary, config, test) exactly as today: `{path: join(cwd, binary.path), requireFile: true}`, `{path: join(cwd, contained.path), requireFile: true}`, `{path: join(cwd, contained.path), requireFile: false}` — this is the explicit, consistent choice and the PR description must state it in one sentence ("containedPaths entries remain host-absolute; only emitted args become repo-relative"). Keep the label as the declared relative form. Keep the argument grammar, ordering, index skipping and every existing phpunit reason string unchanged. Do NOT edit translateDdev: with relative inner args its argv becomes ["exec", "vendor/bin/phpunit", …relative args…], which already contains no host prefix; verify by reading, not by changing.
**Consequences:** Direct phpunit spawn stays correct because verify spawns with cwd = repository root; ddev-wrapped argv becomes fully container-relative. Pre-spawn containment revalidation is unaffected since containedPaths stay absolute. Existing tests that assert absolute -c/test args must be updated to the relative form — that is the one documented byte change to existing expectations.
