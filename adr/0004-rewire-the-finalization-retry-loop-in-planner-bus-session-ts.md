# ADR-0004: Rewire the finalization retry loop in planner-bus-session.ts to feed ids into the repair message

**Status:** Accepted
**Context:** The loop is the shared path for both the claude/bus lane and the native openai progressive lane, so fixing it once serves both. `reason` is a string, but the ids now travel on the thrown error; when the rejection is not a coverage error (unparsable JSON, uninitialized harness) the ids must still come from somewhere, and the progressive controller is the only holder of the contract plus the admitted stories.
**Decision:** In packages/baro-orchestrator/src/planning/adapters/planner-bus-session.ts:
1. Keep `const maxFinalizationAttempts = 3` (:505), the loop bounds (:506), the `candidate` extraction and its `catch { candidate = null }` (:516-521), the `reason` construction and its `/was not initialized by the harness/` augmentation (:531-541), and the `[planner-bus] finalization attempt ${attempt}/${maxFinalizationAttempts} rejected: ${reason}` stderr line (:542-544) exactly as they are.
2. Capture the caught error object in a loop-scoped `let rejectionError: unknown = null` alongside `reason`.
3. Resolve ids once per rejection into `const unowned = missingObligationIdsFromError(rejectionError)` and, when that is empty, `progressive.unownedObligationIds()`.
4. Replace the inline retry literal (:546-553) with `planner.sendUserMessage(buildFinalPrdRepairMessage({ reason, error: rejectionError, unownedObligationIds: unowned }))`. Keep the `if (attempt < maxFinalizationAttempts)` guard and the `continue` (:545,:554). Keep `sendUserMessage` as the delivery call — do not switch transports.
5. Add `let repairMessagesSent = 0`, incremented at each `sendUserMessage` above, declared outside the loop.
6. Add `unownedObligationIds(): readonly string[]` to the progressive controller interface this file consumes (the one already declaring `hasEarlyPlan`, `assertInitialized`, `reconcileFinalCandidate`); implement it in planner-openai-progressive.ts as `unownedObligationIds(obligationContract, session.snapshot().stories)` from obligation-coverage-report.ts, and return `[]` from the disabled stub in planner-harness-progressive.ts (near :118).
7. Keep the parsed-vs-prose guard at :566-567 byte-identical: `if (candidate !== null || !progressive.hasEarlyPlan()) return fail("planner_failed", reason)`. Add ONE further fail-closed condition immediately after it: `if (repairMessagesSent === 0) return fail("planner_failed", reason)` — composition is reachable only after the model was actually given the repair information. Do not reorder or merge these guards.
Do NOT change `fail(...)` (:312-321), the `PlannerBusSessionResult` shape (:279-282), the `plan_complete` payload (:593-606), or ReceiptObserver (:137-151).
**Consequences:** Both lanes get the richer prompt from one edit. The extra `repairMessagesSent` guard is a no-op at the shipped budget of 3 (two repairs precede composition) and only bites if the budget is ever lowered to 1, which is exactly the intent. The controller interface gains one method, so every implementation and test double of it must be updated — the disabled stub and any inline fake in existing tests.
