# ADR-0001: Attach structured missingObligationIds to ArchitectureObligationContractError without changing validator behavior

**Status:** Accepted
**Context:** The retry prompt needs the concrete unowned ids, but today `validateArchitectureObligationCoverage` in "complete" mode throws and only the joined string survives. Re-parsing the message with a regex is brittle; re-running the validator in "partial" mode at the call site duplicates the ownership logic. The goal forbids weakening the validator, and adding a read-only data field to the error it already throws does not change when or whether it throws.
**Decision:** In packages/baro-orchestrator/src/planning/domain/architecture-obligation-contract.ts: give `ArchitectureObligationContractError` (:54-59) a new optional readonly property `readonly missingObligationIds: readonly string[]` defaulting to `[]`, populated only at the existing incomplete-coverage throw site (:327-331) with the same `missingObligationIds` array that builds the message. Do NOT change the message text, the throw condition, the `"partial"`/`"complete"` mode semantics, the returned `ArchitectureObligationCoverageResult` shape (`coveredObligationIds`, `missingObligationIds`), the id regex (:20), the claim regex (:25), the positional id check (:407-414), or any other throw site (:289-308) — other throw sites leave the field `[]`. Export a narrow reader from the same file: `export function missingObligationIdsFromError(error: unknown): readonly string[]` returning `error instanceof ArchitectureObligationContractError ? error.missingObligationIds : []`. Do NOT introduce a new error class and do NOT change `obligationMappingsForStories` (:335-343).
**Consequences:** Callers can recover ids from a rejection without string parsing. Existing tests asserting the error message or coverage result keep passing. Non-coverage contract errors surface an empty id list, so every consumer must handle the empty case explicitly (see the reporting module and the empty-tail message decisions).
