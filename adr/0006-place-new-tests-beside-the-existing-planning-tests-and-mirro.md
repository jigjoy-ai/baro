# ADR-0006: Place new tests beside the existing planning tests and mirror a neighbouring file's harness

**Status:** Accepted
**Context:** Test files live under packages/baro-orchestrator/test/ with subdirectories mirroring src (test/planning/progressive-planning-final-tail.test.ts, test/acceptance/critic-evidence.test.ts, test/execution/gate-registry.test.ts). The runner/import style was not established by scouting, so agents must copy a neighbour rather than introduce a framework choice.
**Decision:** Add packages/baro-orchestrator/test/planning/architecture-obligation-canonicalization.test.ts. Its imports, test-declaration style, assertion library and any stdout-intercept helper MUST be copied from packages/baro-orchestrator/test/planning/progressive-planning-final-tail.test.ts (see its stdout intercept at :670-704). Do not add any test dependency to package.json and do not create a new test directory.

Required cases, one test each: (a) paraphrased `[O-xxx]` claim with a known id is canonicalized, ownership is registered, and exactly one `kind:"warn"` `id:"plan"` activity line is emitted; (b) unknown obligation id still throws; (c) two ids in one claim still throws; (d) duplicate owners of one obligation still throws; (e) a mapping set with three distinct violations throws once and `violationsFromError(error)` returns all three kinds; (f) a story omitting parent invariant ids on an otherwise valid claim is completed with a warn and does not throw, while calling the validator with pre-canonicalized-but-parent-stripped mappings still yields a `missing_parent_invariants` violation; (g) `buildFinalPrdRepairMessage` with a contract contains the exact `renderArchitectureObligationCriterion` output for each unowned id, and is byte-identical to the legacy string when the contract is absent.
**Consequences:** No new dev dependency, no runner change. Existing tests that assert single-violation messages continue to pass because ADR-004 preserves the legacy string when exactly one violation is present; any test asserting a first-failure-wins ordering across multiple violations must be updated to read `violations` instead.
