# ADR-0003: Record in the PR description that the shared-helper form was chosen and that the goalFingerprint loss is erasure, not a missing stamp

**Status:** Accepted
**Context:** The goal requires the fix's form to be explicitly defended, and requires identifying which of two causes (stamp bypass vs. full-file erasure) was at work. Scout evidence settles the second question: the headless progressive bootstrap does stamp (crates/baro-tui/src/main.rs:4117→4130→4137) and no TS file writes prd.json outside the enumerated sites, so the stamp is never bypassed.
**Decision:** The PR description must contain two short sections. (1) 'Form': the preferred shared-helper form in `prd.ts` was adopted, not the conductor-only re-read; justification — the audit found seven full-file writers, of which conductor is one, and `collective-board.ts:495` (not conductor) is the site that drops `goalFingerprint` first; a conductor-local re-read would fix one of seven and duplicate the merge rule six more times. (2) 'Diagnosis': `goalFingerprint` IS stamped on the headless progressive bootstrap path (main.rs:3945 via 4130); it is erased afterwards because `PrdFile` has no such member (prd.ts:122-140) and `normalizePrd` rebuilds a whitelist literal (prd.ts:282-291), so every TS full-file write drops it — cause (b), erasure, confirmed by the test in ADR 4. No stamp is added on any TS write-site; `goalFingerprint` remains Rust-authored.
**Consequences:** No code follow-up. If a later change makes TS author the fingerprint, this ADR must be superseded first.
