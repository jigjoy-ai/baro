# ADR-0003: Canonicalize omitted parent GoalContract invariant ids host-side with a warn, keeping the validator check as a backstop

**Status:** Accepted
**Context:** The goal requires an explicit, documented decision here. Parent invariant ids are host-owned data: they live on `ArchitectureObligationV1.invariantIds` (architecture-obligation-contract.ts:29), are bound against the host GoalContract in `bindArchitectureObligationContract` (:106-131), and the planner prompt explicitly forbids stories from writing them into acceptance text (planner-prompts.ts:78-79, :488, :493). The repo already treats their omission as mechanically repairable: `completeImpliedInvariantIds` (:261-270) plus planner-validation.ts:146-156 do exactly this completion today, just on one path. Alternative considered and rejected: keep the hard rejection at :319-326 as a genuine model-defect signal — rejected because it fails a model for data it was told not to author, and it is repairable with zero authority risk, since the implied ids are read from an obligation the story provably owns via a contract-known id, never from provider JSON.
**Decision:** Missing parent invariant ids on an otherwise valid claim are canonicalized host-side, not rejected. Inside `canonicalizeObligationMappings`, for every acceptance string whose `[O-xxx]` id exists in the contract, union `contract` obligation `invariantIds` into the mapping's `invariantIds` via the existing `completeImpliedInvariantIds(declared, implied)`, and emit one `completed_obligation_parent_invariants` note per (story, obligation) whose ids were actually added. Ids are only ever sourced from the contract obligation the story owns; never from acceptance text, and never for an id absent from `byId`.

The validator's missing-parents check at :319-326 is RETAINED unchanged in wording and remains a fatal violation (kind `missing_parent_invariants`, ADR-004). After this canonicalization it is unreachable via the normal path and stands only as a fail-closed backstop should a caller construct mappings the canonicalizer did not see.

This ADR is the record the goal asks for; the ADR file written into adr/ per repo convention must state this decision and the rejected alternative verbatim.
**Consequences:** Story ownership is registered for paraphrased claims that omitted parent ids, and the completion is always visible as a run-stream warn. Unknown ids, compound claims, and duplicate owners remain rejected — none of them are touched by this rule. Agents must not delete the :319-326 branch; a test asserting it still throws when the validator is handed non-canonicalized mappings directly is required.
