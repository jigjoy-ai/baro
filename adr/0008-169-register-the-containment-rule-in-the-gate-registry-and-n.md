# ADR-0008: #169: register the containment rule in the gate registry and name .baro-scratch as the sanctioned scratch location

**Status:** Accepted
**Context:** gate-registry.ts is described in its own header as the join between enforcement sites and registered ids, with a conformance test joining on GateDisclosure.id, and hook-bridge.ts already pulls surfaceRemedyLines from it so the hook's words and the gate's words are one object. A refused command with no disclosed alternative just makes the agent retry a variant, so the rule needs a sanctioned escape.
**Decision:** Add to src/execution/gate-registry.ts:
  const SHELL_CONTAINMENT: GateDisclosure = { id: "shell-containment", enforcedBy: "src/execution/shell-containment.ts", summary: "Shell commands must stay inside your worktree; scratch checkouts go under .baro-scratch/.", announce: () => [...] }
and include it in BASE_GATES so every story, in every lane, is told up front. The announce() text must (a) open with a line containing the literal token `[gate:shell-containment]`, (b) name the refused shapes (cd outside the worktree, absolute paths outside it, parent/home traversal, nested shell evaluation, redirection through an escaping symlink), and (c) state the remedy verbatim: create scratch checkouts under `<worktree>/.baro-scratch/`, which is inside the worktree and is not part of your write surface for the merge gate.
The refusal reason produced by shellContainmentRefusal for an escaping path operand must also carry the `[gate:shell-containment]` token so the hook denial and the disclosure join on the same id. Do not add `.baro-scratch/` to any story's declared write surface, and do not add it to .gitignore in this run.
**Consequences:** The gate-registry conformance test will require the new id to name a module that exists, so the ADR-007 extraction must land in the same story. Because SHELL_CONTAINMENT is in BASE_GATES, the base prompt grows for every lane, which is intended: the native lane already enforces the rule and previously never announced it.
