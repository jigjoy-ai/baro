# ADR-0001: Supersede the pending review wait instead of failing when a newer non-null terminal arrives

**Status:** Accepted
**Context:** src/acceptance/turn-review.ts:207-218 currently fails the story with `review_uncorrelated` whenever `observeResult` sees a truthy terminalId while `waitingTerminalId` is set to a different id. `TurnReviewMailbox.waitFor` throws if an active wait already exists (69-73), so supersession cannot be implemented by simply calling `waitFor` again. Alternatives rejected: allowing multiple concurrent mailbox waits (changes mailbox invariants and delivery routing for no benefit); racing both waits (the goal says the latest candidate decides).
**Decision:** In `StreamingTurnLifecycle.observeResult`, delete the failure branch at 207-218 and replace it with supersession, executed in exactly this order:
1. Capture `const superseded = this.waitingTerminalId` (may be null).
2. Set `this.waitingTerminalId = terminalId` BEFORE cancelling, so the cancelled old wait's `applyWaitResult(superseded, …)` hits the existing guard at line 245 and returns without touching state.
3. If `superseded !== null && superseded !== terminalId`: call `this.reviews.cancelActive()` and `this.reviews.discard(superseded)`, then invoke the supersession notification from ADR-002.
4. Start the new wait exactly as the current happy path does: `void this.reviews.waitFor(terminalId, { timeoutMs: this.options.reviewTimeoutMs }).then((result) => this.applyWaitResult(terminalId, result))`.
Add `discard(terminalId: string): void { this.queued.delete(terminalId) }` as a new public method on `TurnReviewMailbox` next to `cancelActive()` (107-109). Do NOT change `deliver`, `waitFor`, `dequeue`, `cancelActive`, `applyWaitResult`, `fail`, `stop`, the duplicate-of-awaited guard at 186-190, the non-review path at 192-196, or `turnsObserved` accounting. Do NOT touch src/harness/one-shot/turn-review.ts.
**Consequences:** A late `Critique` for a superseded terminal can no longer be consumed: `deliver` will not match the active wait (its terminalId is the new one) and the queue entry is dropped at supersession time, so a verdict arriving after supersession is queued-and-never-dequeued, i.e. ignored as stale — and the cancelled wait's own result is discarded by the line-245 guard. `waitingTerminalId` remains single-slot; there is still at most one mailbox wait at a time. `turnsObserved` now increments per distinct terminal as before, so `maxTurns` behaviour is unchanged.
