# ADR-0010: Place tests in the existing files named by the acceptance command

**Status:** Accepted
**Context:** The acceptance run lists declared-verification.test.ts, verify.test.ts and the prd and planner-validation test files. No new runner configuration is wanted.
**Decision:** test/verification/declared-verification.test.ts:
- `judgeTestBudget` cases, with each exact rejection string.
- `resolveDeclaredBudget`: max of accepted requests, first story wins a tie.
- `createVerifyPlan` with no testBudgets admits 8 and the overflow reason matches /safe limit is 8 \(default; no story negotiated testBudget\)/.
- A valid `{commands:12, reason:'x'}` on S1 with 12 unique `npm test -- focusN` requirements (package.json has a test script) admits 12 with no overflow entry, and `plan.declaredBudget.negotiatedBy === 'S1'`.
- Blank reason, commands 12.5 and commands 25 each fall back to 8, with a rejected decision naming the story and the reason.
- `mergeVerifyPlans` keeps 12 negotiated additions.

test/verification/verify.test.ts:
- `recommendedVerifyTimeoutMs` for the negotiated plan minus the default plan equals 4 × 608_000.
- `recommendedMergedVerifyTimeoutMs(baseline, 12)` minus `(baseline)` equals 4 × 2 × 608_000.

test/prd.test.ts and test/planner-validation.test.ts: as described in the contract and planner-gate ADRs.

Shipping: `npm run typecheck` passes in packages/baro-orchestrator, and the PR description contains 'Closes #108'.
**Consequences:** The conformance test must keep passing unchanged, and `cargo test` must pass for the Rust changes.
