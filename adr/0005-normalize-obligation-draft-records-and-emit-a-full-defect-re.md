# ADR-0005: Normalize obligation draft records and emit a full-defect repair prompt in the segment compiler

**Status:** Accepted
**Context:** architect-obligation-segments.ts already computes the missing/unexpected key split at :477-488 but collapses it into one thrown message, and its own repair loop feeds back a single safeReason string (:284, :370-374). The goal requires drift tolerance plus full-defect repair feedback here too, without touching the 3-attempt budget at :278-283.
**Decision:** In src/planning/domain/architect-obligation-segments.ts:
- Normalize the top-level response record with `normalizeRecordKeys(value, ["schemaVersion", "obligations"], "", onNote)` before the exactRecord check at :432-436, and each draft with `normalizeRecordKeys(candidate, DRAFT_KEYS or [...DRAFT_KEYS, "id"], `obligations[${index}]`, onNote)` before the check at :461-493. `DRAFT_KEYS` (:453-460) remains the single source of expected names; `exactRecord` (:743-750) is unchanged and its unexpected-key branch stays as a backstop.
- Evidence entries stay plain strings — do NOT normalize inside them, and do NOT touch architecture-obligation-contract.ts (its 1..MAX_EVIDENCE_ITEMS bound at :428-436, per-item boundedText and duplicate rejection remain the authority).
- Export `const ARCHITECT_OBLIGATION_DRAFT_SCHEMA_SUMMARY: string` from this module: a short inline restatement of the draft JSON shape `{"schemaVersion":1,"obligations":[{"adrIds":[],"invariantIds":[],"subject":"","scenario":"","expectedOutcome":"","evidence":[]}]}` plus one line naming the per-field bounds. It must be a NEW constant in this file; do NOT edit architect-prompts.ts or planner-prompts.ts.
- The `repair` string built at :284/:370-374 becomes: `"Your draft was rejected. Fix every defect listed below in one reply.\n\nDefects (${n}):\n" + formatDefectList(defects) + "\n\nExpected schema:\n" + ARCHITECT_OBLIGATION_DRAFT_SCHEMA_SUMMARY`. `safeReason` (:734-741) is applied per defect message rather than to the whole block, and its 1000-char cap is replaced by the 400-per-defect / 4000-total caps of `formatDefectList`; the control-character stripping and whitespace collapsing behaviour is preserved.
- The attempt count (3) and the bisection routing for `ArchitectObligationOutputLimitError` are unchanged.
**Consequences:** The single production caller (scripts/run-architect.ts:823) reads only `.decisionDocument` and is unaffected. Existing message-regex tests keep passing because a single-defect rejection still produces the same message text. The new schema-summary constant duplicates shape information that also appears in prompts; it is deliberately a separate constant so the prompt files stay untouched per the non-goals.
