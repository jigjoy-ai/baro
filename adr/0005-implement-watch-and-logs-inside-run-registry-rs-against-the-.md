# ADR-0005: Implement `watch` and `logs` inside run_registry.rs against the existing BaroEvent parser

**Status:** Accepted
**Context:** docs/tui-protocol-v3.md §5 lists story_start, critique, story_merged/merge_failed and the terminal event; orchestrator_client.rs:196-228 already deserializes stream lines into BaroEvent. A second, divergent protocol parser in watch would rot.
**Decision:** run_registry.rs adds `pub fn run_logs(args: &[String]) -> i32` and `pub fn run_watch(args: &[String]) -> i32`. Both resolve the run id argument through the existing `find`/`live_runs` path first, and fall back to `log_path_for(id)` when the record is already reaped; if neither file exists, print `no log for run '<id>'` to stderr and return 2.
`logs`: prints the file verbatim to stdout; with `--follow`, tails (poll every 200ms) until the registry record disappears; returns 0.
`watch`: tails the same file, deserializes each non-empty line with serde_json into the crate's existing event type used by orchestrator_client (import it rather than defining new structs), and prints one human-readable line per milestone event only — story_start, critique, story_merged, merge_failed, and the terminal done event; all other events and unparseable lines are ignored. Exit code comes from a pure, unit-tested function in the same file: `pub fn watch_exit_code(terminal: Option<&serde_json::Value>) -> i32` -> 0 when the terminal event reports success (`success == true`, or `status`/`result` equal to "success"), 1 for any other terminal event, and 1 when the tail ends with no terminal event (registry record gone). Inline tests feed a synthetic log file of JSON lines and assert both the printed milestone lines and the exit code for success, failure, and truncated-log cases.
**Consequences:** Wire protocol version stays v3 and no event struct is added or renamed. If the shared event type is not `pub` at the needed path, S2 may only widen visibility inside run_registry's import — a required type change must be reported, not made in a foreign file.
