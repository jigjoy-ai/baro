# ADR-0006: Do not extract a shared canonicalization helper across the three repair sites

**Status:** Accepted
**Context:** The goal permits a shared helper only if it contorts none of the three sites. The three recipes are structurally different: the planner gate rewrites acceptance criterion TEXT via `canonicalObligationAcceptance` and mutates the PRD in place; the architect obligation path assigns ids positionally and repairs from a defect list with output-limit bisection; the new predicate path substitutes whole records matched by index/id. Their canonical sources, match keys, and note types all differ, and `canonicalObligationAcceptance` has no architect-side caller at all.
**Decision:** Add no new cross-cutting helper module and move no code between `src/planning/domain/architecture-obligation-contract.ts`, `src/planning/domain/architect-obligation-segments.ts`, and `src/goal/goal-constraint-appendix.ts`. Convergence is limited to reusing the primitives already exported by `src/contract/contract-normalization.ts` — `ContractDefect`, `ContractNote`, `NoteSink`, `contractDefects`, `formatDefectList`, `joinDefectMessages`, `normalizeRecordKeys`. All new matching and restoration logic lives in `src/goal/goal-constraint-appendix.ts`, which is the single owner. Do not touch `planner-validation.ts`, `planner-openai.ts`, `architect-openai.ts`, or `architect-bus-session.ts` beyond nothing at all.
**Consequences:** Existing architect and planner obligation gate behavior is provably unaffected — no file on those paths is edited. The ADR from ADR-007 records the rejected shared-helper option so the question is not reopened.
