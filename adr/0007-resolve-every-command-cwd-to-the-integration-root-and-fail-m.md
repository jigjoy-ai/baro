# ADR-0007: Resolve every command cwd to the integration root and fail missing directories without retry

**Status:** Accepted
**Context:** `commandCwd = c.cwd ?? cwd` (verify.ts:1179) trusts an absolute spec cwd, which can point at a story worktree that the merge already removed. The missing-dir branch (verify.ts:1180-1186) already fails, but the retry loop (verify.ts:1290-1294) sees a plain `failed` and re-runs it against the same absent path.
**Decision:** In src/verification/verify.ts:
1. Add a non-exported `resolveCommandCwd(runCwd: string, commandCwd: string | undefined): string`: returns `runCwd` when `commandCwd` is undefined; returns `commandCwd` when `resolve(commandCwd)` equals `runCwd` or is strictly under `runCwd` (compare via `relative(runCwd, resolved)` being non-empty, not starting with `..`, and not absolute); otherwise, if `basename`-relative remapping is possible — i.e. the spec cwd is under a `baro-worktrees/<runId>/<agentId>` sibling — return `join(runCwd, relative(<that worktree root>, resolved))` when that path exists, and `runCwd` in every other case. Apply `pathAliases()`/`canonicalPath` from src/runtime/worktree-path.ts:10-25 before comparing so /var vs /private/var does not cause a false mismatch.
2. Replace `const commandCwd = c.cwd ?? cwd` at verify.ts:1179 with `const commandCwd = resolveCommandCwd(cwd, c.cwd)`.
3. Keep the existing `!existsSync(commandCwd)` branch (verify.ts:1180-1186) returning `status: "failed"` with tail exactly `verification working directory is missing: ${commandCwd}`, and additionally set a new outcome field `retryable: false`. Never retry, never re-resolve, never spawn in that branch.
4. Add `retryable?: boolean` to the command-outcome type in verify.ts (near the `firstFailureTail`/`retriedAfterFailure` fields, verify.ts:83-87) and change the retry condition at verify.ts:1290-1294 to `outcome.status === "failed" && outcome.retryable !== false && !c.preflightFailure && isRunLevelCommand(c)`. Do not mirror `retryable` into src/events/verification.ts.
**Consequences:** Declared commands scoped with `cd <dir>` (declared-verification.ts:198,234) now fall back to the integration root when their directory is outside it, instead of failing — that is the intended "falls back to the integration root" branch. The containment recheck at verify.ts:1188-1200 runs against the resolved cwd and is unchanged.
