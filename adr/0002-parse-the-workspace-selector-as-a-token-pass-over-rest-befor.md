# ADR-0002: Parse the workspace selector as a token pass over `rest`, before the '--' split

**Status:** Accepted
**Context:** translatePackage today treats rest[0] !== "--" as a hard rejection (:357-374). The selector must be recognised for both 'npm test' (rest = tokens.slice(2)) and 'npm run <script>' (rest = remaining), must appear before any '--', and at most once. Reusing the existing '--' logic unchanged after stripping the selector keeps containment behaviour identical.
**Decision:** Add a module-local helper in declared-verification.ts, `extractWorkspaceSelector(rest: readonly string[]): { name?: string; declared?: readonly string[]; rest: readonly string[]; reason?: string }`, and call it once in translatePackage immediately after `rest` is computed (before the current rest[0] === "--" check). Grammar: scan rest left to right; stop scanning at the first element equal to "--". Recognised forms, exactly three: (a) "-w" followed by a value token, (b) "--workspace" followed by a value token, (c) a single token matching /^--workspace=(.+)$/. A value token is invalid if absent or if it starts with "-". `declared` is the exact declared token(s) as written (e.g. ["-w","@baro/orchestrator"] or ["--workspace=app"]). The selector tokens are removed from `rest`; all other tokens keep their original order and are returned as the new `rest`, which then flows into the EXISTING unchanged '--' / safeFocusedArg / focusedPathRequirement logic. If a second selector occurs anywhere before "--", reject. If "-w", "--workspace", or a "--workspace=" token occurs at or after the "--" element, reject. When no selector is present, `name` and `declared` are undefined and `rest` is returned identical to the input (reference-equal or shallow copy — behaviour must be byte-identical to today).
**Consequences:** Focused '--' handling, safeFocusedArg containment against the repo root, and focusedPathRequirement entries are untouched. `npm run test -- --filter x` and every other root-scoped declaration keeps the exact same spec bytes.
