# ADR-0012: Accept the workspace selector between `run` and the script name in translatePackage

**Status:** Accepted
**Context:** extractWorkspaceSelector (declared-verification.ts:346-401) is already correct for tokens after the script name, but translatePackage (:451-475) destructures `[, operation, maybeScript, ...remaining]` before calling it, so `npm run -w packages/baro-orchestrator typecheck` makes script = "-w" and dies on SAFE_SCRIPT_NAME (:472). Rewriting the tokenizer would risk the existing trailing-selector, one-selector and post-`--` rules.
**Decision:** Change only the ordering inside translatePackage: for `operation === "run"`, call `extractWorkspaceSelector(parsed.tokens.slice(2))` FIRST; on `selector.reason` return incomplete(requirement, selector.reason); then take `script = selector.rest[0]` and `rest = selector.rest.slice(1)`; missing script keeps the existing message `package tests must use '<manager> test' or '<manager> run <script>'`. For `operation === "test"` behavior is unchanged (selector extracted from tokens.slice(2), no script token to peel). extractWorkspaceSelector itself is NOT modified: at most one selector, `--workspace=<name>` / `-w <name>` / `--workspace <name>` all accepted, a selector at or after `--` still rejected with `workspace selector must appear before '--'`, a missing/dash-prefixed name still rejected with `workspace selector requires a name`. resolveWorkspaceAuthority (:411-449) and all trust/resolution semantics stay byte-identical.
test/verification/declared-verification.test.ts gains, in the existing node:test house style with exact argv assertions: `npm run -w packages/baro-orchestrator typecheck`, `npm run --workspace packages/baro-orchestrator typecheck`, `npm run --workspace=packages/baro-orchestrator typecheck`, `npm run -w pkg typecheck -- test/x.test.ts`, duplicate selector on both sides of the script name (rejected, one-selector message), `npm run -w typecheck` (missing name), `npm run typecheck -- -w pkg` (rejected, post-`--` message), plus regressions for the existing trailing-selector forms and `npm test -w pkg`.
**Consequences:** Only one function body changes, so the focused-argument policy, `--` handling and unknown-workspace errors are unaffected. Both the pre-script and post-script positions must keep producing identical VerifyCommandSpec argv, which the new tests assert directly.
