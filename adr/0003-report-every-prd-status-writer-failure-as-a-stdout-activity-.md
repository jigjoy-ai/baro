# ADR-0003: Report every prd-status writer failure as a stdout activity event instead of a stderr line

**Status:** Accepted
**Context:** prd-status-writer.ts:32 defaults `warn` to process.stderr, so the unknown-story branch (:45-53) and the shared load/save catch (:60-68) are invisible to an operator watching the run. The repo convention for operator-visible failures is a BaroEvent {type:"activity"} written by emit() on stdout (tui-protocol.ts:160-170, :223-234), injected as a sink that defaults to emit (forwarders/dialogue.ts:7,13,65-71; forwarders/progress.ts:287-292). stderr is not part of the NDJSON stream the TUI reads. Keeping both `warn` and a new sink would double-report, so the option is replaced rather than added.
**Decision:** In packages/baro-orchestrator/src/execution/prd-status-writer.ts, remove the `warn` option and replace it with `emitActivity?: (event: BaroEvent) => void`, defaulting to `emit` imported from `../tui-protocol.js`. Emit exactly these events, keeping the existing per-story dedupe sets (warnedUnknown, warnedWriteFailure) so each story reports each failure class at most once:
- unknown story: `{ type: "activity", id: storyId, kind: "warn", text: `[prd-status] no story '${storyId}' in ${prdPath}; status not recorded`, ok: false }`
- load or save failure: `{ type: "activity", id: storyId, kind: "error", text: `[prd-status] could not record '${storyId}' in ${prdPath}: ${message}`, ok: false }` where `message = error instanceof Error ? error.message : String(error)`.
No other event fields are set (no tool/path/op). Failures still never rethrow into the event bus. Nothing is written to stderr. orchestrate.ts:844 continues to pass no sink, so production uses `emit`. Update the existing prd-status-writer test file under packages/baro-orchestrator/test/ to inject `emitActivity` (collecting events into an array) in place of `warn`, and assert the exact `kind` and `text` above for: unknown story, load throw, save throw, plus one assertion that a missing prd.json file produces no event at all.
**Consequences:** Operators see writer failures inline in the run stream. Any caller or test that passed `warn` breaks at compile time, which is intended and confined to the writer's own test file. This story owns prd-status-writer.ts and its existing test file; it must land together with the wiring ADR since both touch that file.
