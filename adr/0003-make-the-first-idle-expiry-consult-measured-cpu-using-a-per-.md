# ADR-0003: Make the first idle expiry consult measured CPU using a per-run spawn-time baseline

**Status:** Accepted
**Context:** exec-file-cli.ts:49-56 hardcodes `previous === null → active`, so a genuinely idle, silent process survives its first window. exec-file-cli.test.ts:214 fires the single armed 900ms window once through an injected clock and requires a kill, and the goal requires that silent AND idle processes die at the end of the no-output window. A baseline cannot be seeded into execFileCliRaw's `cpuSample`, because exec-file-cli-cpu-watchdog.test.ts:149 asserts the probe receives `previous === null` at the first expiry and that test must keep passing. Rejected: two-sample micro-probing at expiry (unmeasurable at `ps` resolution) and killing unconditionally when previous is null (would kill silent-but-computing commands at the first window).
**Decision:** Add `createDefaultCpuActivityProbe(rootPid: number | undefined): CpuActivityProbe` to packages/baro-orchestrator/src/harness/process-cpu-activity.ts, and move the `CpuActivityProbe` type there, re-exported from exec-file-cli.ts (`export type { CpuActivityProbe }`) so existing importers such as test/harness/exec-file-cli-cpu-watchdog.test.ts:9 keep compiling.
Behaviour of the factory:
- On construction it starts one `sampleProcessTreeCpu(rootPid)` and retains the promise as the spawn baseline. `rootPid === undefined` ⇒ the baseline resolves to an unobservable sample.
- Call with `previous === null`: await the baseline, take a fresh sample, return `{ active: cpuAdvanced(baseline, current), sample: current }`.
- Call with `previous !== null`: unchanged semantics — `{ active: cpuAdvanced(previous, current), sample: current }`.
- Unobservable samples (either side) still count as active, per process-cpu-activity.ts:121.
In exec-file-cli.ts, replace the module-level `defaultCpuActivityProbe` const with, immediately after `spawn(...)`: `const cpuActivityProbe = options.cpuActivityProbe ?? createDefaultCpuActivityProbe(child.pid)`. Delete the `/** The first expiry has no baseline… */` comment and its rule. Do not otherwise change onIdleExpiry (:232-269), petIdle (:271-277), the generation guard (:261), the CPU_PROBE_TIMEOUT_MS race (:245-251) or terminate() (:188-198).
**Consequences:** exec-file-cli.test.ts:214 now rejects with `produced no output for 900ms — presumed hung` at the first expiry, and that test file must NOT be edited (see ADR-005). exec-file-cli-cpu-watchdog.test.ts:137 keeps passing because it injects its own probe and still sees `previous === null` first. exec-file-cli-cpu-watchdog.test.ts:196 ('grants the first expiry an extension under the real default probe') encodes the rule being removed and must be rewritten under ADR-005. Production effect: a silent command with no CPU progress across its tree now dies at the end of its first idle window (180s/300s per liveness.ts, 5min in verify.ts:34) instead of the second; silent-but-computing commands are still extended; the absolute ceiling still applies regardless (verify.ts:37).
