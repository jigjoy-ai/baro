# ADR-0002: Create planning/domain/obligation-coverage-report.ts as the single owner of gap computation and id formatting

**Status:** Accepted
**Context:** Three sites need the same two things — "which obligation ids are still unowned given the stories admitted so far" and "how to render an id list into a bounded prompt/log line": the finalization retry message, the fragment publish receipt, and the empty-tail failure message. No id-list formatter exists anywhere; today callers inline `ids.join(", ")` (architecture-obligation-contract.ts:329, final-tail-tolerance.ts:75, runtime-replan.ts:411). Left unowned, three agents would write three different regexes and three different truncation rules.
**Decision:** Add packages/baro-orchestrator/src/planning/domain/obligation-coverage-report.ts exporting exactly three functions and no state:
1. `export function unownedObligationIds(contract: ArchitectureObligationContractV1 | null | undefined, stories: readonly PrdUserStory[]): readonly string[]` — returns `[]` when `contract` is null/undefined or has no obligations; otherwise computes `validateArchitectureObligationCoverage(contract, obligationMappingsForStories(stories), "partial").missingObligationIds`. Wrap the call in try/catch: on any throw, return `contract.obligations.map((o) => o.id)` (conservative — report everything as unowned rather than under-reporting). Never call the validator in `"complete"` mode here; this function must never throw.
2. `export function formatObligationIdList(ids: readonly string[]): string` — `""` for empty; otherwise `ids.slice(0, 40).join(", ")` plus `` ` … (+${ids.length - 40} more)` `` when `ids.length > 40`.
3. `export function obligationGapSummary(unowned: readonly string[], total: number): string` — `` `${unowned.length}/${total}` `` when `unowned.length === 0`, else `` `${unowned.length}/${total}: ${formatObligationIdList(unowned)}` ``.
Use the story type already used by `obligationMappingsForStories`. Do NOT duplicate the `/\[O-\d+\]/u` presence heuristic currently at planner-openai-progressive.ts:286 anywhere — it is deleted (see the receipt decision) and no replacement regex is written outside architecture-obligation-contract.ts. Do NOT add a dependency; no new npm package for any part of this goal.
**Consequences:** All three sites import from one module, so truncation and wording drift is impossible. The catch-all fallback means a malformed claim (e.g. an unknown id in acceptance text) is reported as a full gap rather than crashing publish, which is louder but never silently permissive. `validateArchitectureObligationCoverage` itself is untouched.
