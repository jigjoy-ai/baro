# ADR-0006: Cover presence, absence, activity formatting and verdict-schema stability in the existing test file

**Status:** Accepted
**Context:** test/acceptance/critic-evidence.test.ts already builds real temp git repositories with local `git(cwd, ...args)` (1513-1515) and `withTempDir` / `source(agentId)` / `joinWithCapture` from ../execution/helpers.js (line 41), so the wiring is testable without new fixtures infrastructure; the exact string formats are already unit-tested in test/acceptance/altitude.test.ts and must not be re-asserted from a hand-written literal built in the new tests.
**Decision:** Add tests to packages/baro-orchestrator/test/acceptance/critic-evidence.test.ts (append; do not restructure existing describes), using node:test + node:assert/strict in the file's existing style:
1. Presence: temp git repo, commit a tracked file of >=1500 lines, capture baseSha, then append >=80 lines and commit/leave dirty; call `prepareCriticEvaluation(criteria, resultText, "story-1", { resolveRepositoryTarget: () => ({ cwd, baseSha }), emitActivity: spy, ... })` and assert the returned prompt contains `"## Altitude findings (advisory)"`, contains a line matching `/^src\/big\.ts — \d+ total lines, \+\d+ this story$/m`, and contains the advisory sentence produced by `renderAltitudeEvidenceSection` (obtain the expected sentence by importing `renderAltitudeEvidenceSection` from ../../src/acceptance/altitude.js rather than duplicating the literal).
2. Absence: same harness with a small file (or no qualifying growth) — assert the prompt does NOT include `"## Altitude findings (advisory)"` and that the spy recorded zero events.
3. Activity, one finding: assert the spy received exactly one event deep-equal to `{ type: "activity", id: "story-1", kind: "warn", text: "altitude: <path> at <N> lines grew by <M>" }` with N/M taken from the section the same run produced.
4. Activity, multiple findings: two qualifying files, assert exactly one event whose `text` is the single joined line containing both `"altitude: "` occurrences separated by `"; "`.
5. Segmentation: a criteria set that forces multiple segments still yields exactly one emitted event and the advisory section present in every returned prompt.
6. Verdict schema unchanged: import the verdict schema/prompt exports from ../../src/acceptance/critic-verdict.js and assert their current top-level property names/shape are unchanged, and that no prompt produced by buildEvalPrompt without an altitude section mentions "Altitude".
Generate large files programmatically (e.g. `Array.from({length: 1600}, (_, i) => \`const l${i} = ${i};\`).join("\n")`) — do not commit fixture files to the repository.
**Consequences:** All acceptance criteria are covered by real assertions, so the escape hatch of testing only a pure formatter is not needed; if any of tests 3-5 proves infeasible in practice, the fallback is to assert the formatting via the already-exported altitudeActivityText and record the integration gap in the PR description.
