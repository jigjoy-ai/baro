# ADR-0002: Route all seven full-file src/ write sites through persistPrdPreserving and leave prd-status-writer.ts untouched

**Status:** Accepted
**Context:** The audit found nine write sites, not the four named in the goal. prd-status-writer.ts:64 is the OWNER of the per-story fields and already does load-modify-write; routing it through the helper would be a no-op at best and would blur ownership, and the goal forbids changing it. collective-board.ts:495/1580/3111 were not named in the goal but are the sites that actually erase `goalFingerprint` on the first admitted progressive fragment (:495) and clobber `mergeStatus` from a stale snapshot (:1580, loaded once at :1069) — omitting them would leave the defect live.
**Decision:** Replace the write call at each of these sites with `persistPrdPreserving`, passing no `opts` (no current caller owns a preserved field):
- `packages/baro-orchestrator/src/execution/conductor.ts:848-851` — `const persist = this.opts.persistPrd ?? persistPrdPreserving;` (import `persistPrdPreserving` from `../prd.js`, drop the now-unused `savePrdAtomic` import if it has no other use). The `opts.persistPrd` seam, its type `(path: string, prd: PrdFile) => void` (conductor.ts:105) and both call sites (514, 719) are unchanged; update the doc comment at conductor.ts:100-104 to say the default preserves foreign-owned fields.
- `packages/baro-orchestrator/src/execution/runtime-replan-coordinator.ts:94` — default becomes `opts.persist ?? persistPrdPreserving`; line 296 is unchanged.
- `packages/baro-orchestrator/src/orchestrate.ts:714` and `:1087` — `savePrd(...)` → `persistPrdPreserving(...)`. These two sites become atomic as a side effect; that is intended.
- `packages/baro-orchestrator/src/execution/collective-board.ts:495`, `:1580`, `:3111` — `savePrdAtomic(...)` → `persistPrdPreserving(...)`. Keep the existing `this.prd = prd` assignment at :495-496 as-is.

Do NOT modify `packages/baro-orchestrator/src/execution/prd-status-writer.ts` — its `save = savePrdAtomic` default (line 34) and its load-modify-write closure (42-84) stay exactly as they are. Do NOT delete or deprecate `savePrd`/`savePrdAtomic`; they remain exported and are still the status-writer's default and the tests' primitive.
**Consequences:** After this change the only remaining direct `savePrdAtomic` caller in src/ is prd-status-writer.ts, which is the field owner — the invariant is checkable by grep. collective-board.ts gains an import from `../prd.js` it may already have. Any future full-file writer must use the helper; state that in the PR description. Behaviour on a missing prd.json is unchanged at every site.
