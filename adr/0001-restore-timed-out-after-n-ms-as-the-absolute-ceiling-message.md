# ADR-0001: Restore `timed out after <N>ms` as the absolute-ceiling message, with the ceiling distinction as an appended clause

**Status:** Accepted
**Context:** exec-file-cli.ts:210-212 currently produces `exceeded the absolute limit of ${options.timeout}ms — terminated`, which matches neither /timed out/ (test/harness/exec-file-cli.test.ts:155) nor /timed out after 50ms/ (test/run-architect-outcome.test.ts:309). The goal forbids replacing the established phrase; any idle-vs-ceiling distinction must be an added clause. Rejected: adding a second alias message, or loosening the tests.
**Decision:** In packages/baro-orchestrator/src/harness/exec-file-cli.ts, the absolute-timeout callback (currently :209-215) must build exactly:
`${command} timed out after ${options.timeout}ms — exceeded the absolute command ceiling`
Keep `err.killed = true` and `terminate(err)` unchanged. Do NOT change the idle message, which stays exactly `${command} produced no output for ${idleMs}ms — presumed hung` (exec-file-cli.ts:224-230); the trailing `— presumed hung` clause is anchored by exec-file-cli-cpu-watchdog.test.ts:185.
Before editing, grep the repo for both /exceeded the absolute limit/ and /timed out/ and keep every consumer green. Specifically: src/integration/repository-command.ts:66 (`/timed out|no output/iu`) must stay untouched — the new wording still matches it. Any assertion on the old ceiling wording that lives in an S2-owned test file (test/harness/exec-file-cli-cpu-watchdog.test.ts, test/verification/verify.test.ts, test/verification/verify-run-level-retry.test.ts) must be updated to the restored wording; assertions in any other file must be left alone and must keep passing.
**Consequences:** Both ceiling failures (exec-file-cli.test.ts:155 and run-architect-outcome.test.ts:309) become message-shape-satisfied provided ADR-002 holds. Downstream tails rendered by verify.ts:1076-1081 now read `timed out after …`, so operator-facing text changes; that is intended by the goal. No other module needs a wording branch.
