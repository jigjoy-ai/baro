# ADR-0006: #165: scope the 8000-character limit to the interactive prompt in the Rust intake and report the unread range

**Status:** Accepted
**Context:** The limit the goal names is not in TypeScript: MAX_MESSAGE_CHARS=8_000 (conversation/mod.rs:27) is enforced in begin_request (session.rs:121) through validate_text (contract.rs:366, counting UTF-16 code units to match the TS planner), and a second cap MAX_GOAL_CHARS=8_000 sits downstream in progressive_planning.rs:21 (normalize_goal :214-218, counting chars()). Both intake paths funnel through submit_conversation_message (main.rs:3818); resolve_goal (cli.rs:270-286) applies no length check, and detach.rs:32-47 re-passes the file text positionally so the child revalidates the identical text. The two caps must move together or the goal-file path fails one layer deeper.
**Decision:** Thread the provenance through instead of raising a shared constant.
- Add `pub enum MessageSource { InteractivePrompt, GoalFile }` in crates/baro-tui/src/conversation/mod.rs beside MAX_MESSAGE_CHARS, and add `pub const MAX_GOAL_FILE_CHARS: usize = 120_000;` there (UTF-16 code units, the intake context ceiling).
- ConversationSession::begin_request (session.rs:121) takes the source; validate_text (contract.rs:366) takes it too and applies MAX_MESSAGE_CHARS for InteractivePrompt and MAX_GOAL_FILE_CHARS for GoalFile. The control-character and bidi-override rejections (contract.rs:373-381) stay identical for both sources.
- submit_conversation_message (main.rs:3818) gains the source parameter: main.rs:1451-1463 passes MessageSource::GoalFile (including the detach re-spawn, whose positional goal must still be treated as GoalFile — detach.rs must record the provenance it strips, e.g. by passing an explicit marker flag rather than a bare positional), and main.rs:2532-2535 passes MessageSource::InteractivePrompt.
- Over MAX_GOAL_FILE_CHARS, a GoalFile goal is never refused: keep the first MAX_GOAL_FILE_CHARS UTF-16 units and prepend one line to the intake turn of exactly the form `note: goal truncated for intake; read characters 1-<kept> of <total>; characters <kept+1>-<total> were not read`. InteractivePrompt keeps today's hard error and today's error text.
- normalize_goal (progressive_planning.rs:214-218) applies MAX_GOAL_CHARS only to interactive-sourced goals and MAX_GOAL_FILE_CHARS to goal-file ones, using the same truncation note rather than an error.
**Consequences:** This is the only story that edits crates/, so it is verified with cargo build and cargo test -p baro-tui and cannot conflict with the four TypeScript stories. Callers of begin_request/validate_text/submit_conversation_message all need the new argument; the compiler enumerates them. The 120_000 ceiling is a named constant in one place so tightening it later is a one-line change. Truncation is silent to no one: the note is part of the intake turn itself.
