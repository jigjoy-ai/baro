# ADR-0003: Resolve the workspace name against VerifyJavaScriptPackageManager entries by package name or repo-relative directory

**Status:** Accepted
**Context:** VerifyJavaScriptPackageManager carries only {cwd?, manager, declaredVersion?} (verify.ts:137-143); there is no name field, and workspace entries are exactly those with cwd !== undefined (verify.ts:404-409). Names must therefore be resolved by reading each workspace's package.json, or by comparing the repo-relative directory. Globs are a non-goal.
**Decision:** Add a module-local helper `resolveWorkspaceAuthority(cwd: string, name: string, managers: readonly VerifyJavaScriptPackageManager[]): { authority?: VerifyJavaScriptPackageManager; workspaceDir?: string; reason?: string }` in declared-verification.ts; it is the single owner of this logic. Steps, in order: (1) Read the ROOT package.json via the existing readManifest(join(cwd,"package.json")); if it is missing/invalid, or `manifest.workspaces` is absent (neither an array nor an object with a `packages` array), reject with the ADR-004 no-workspaces reason. (2) Candidates = managers.filter(m => m.cwd !== undefined). For each candidate compute `rel = relative(resolve(cwd), resolve(m.cwd!)).replace(/\\/g, "/")`. (3) Normalise the declared name once: `wanted = name.replace(/\\/g, "/").replace(/^\.\//, "").replace(/\/+$/, "")`. (4) Match a candidate when either `rel === wanted` (repo-relative directory match) OR the candidate's own package.json at m.cwd parses and its `name` field is exactly === `name` (raw declared name, not normalised — package names may not be path-normalised). Path match is attempted first; the first match in `managers` order wins. (5) No match → reject with the ADR-004 unknown-workspace reason, listing the sorted, de-duplicated `rel` values as candidates. Never expand or interpret glob characters in `name`; a name containing "*" simply fails to match and is rejected as unknown.
**Consequences:** Workspace discovery stays owned by verify.ts; the translator only consumes the already-computed manager list, so unsupported workspace patterns keep failing at plan time as they do now. A workspace whose package.json is unparseable is still selectable by its directory path.
