# ADR-0003: #168: re-resolve the verification cwd at spawn and gate story-worktree cleanup on referencing verifications

**Status:** Accepted
**Context:** resolveCommandCwd (command-cwd.ts:44-66) already knows how to remap a sibling story worktree path into the run cwd, and verify.ts:1261 is its only production consumer, but the cwd handed to post-merge and run-level verification is captured earlier in orchestrate.ts, so a story worktree removed by cleanup can still be the cwd of an in-flight verification. The integration worktree at <tmpdir>/baro-worktrees/<runId>/__run (integration-worktree.ts:12-16) is the correct root and is already threaded through orchestrate.ts:850. A vanished cwd is currently reported as a failed command (verify.ts:1262-1269), which reads as a test failure.
**Decision:** Do both halves of the fix.
1. cwd source of truth: post-merge and run-level verification take a resolver, not a captured string. Add to command-cwd.ts:
   export type VerifyCwdResolver = () => string
   export function integrationCwdResolver(integrationRoot: string, repoRoot: string): VerifyCwdResolver
VerifyBuildOptions gains `resolveRunCwd?: VerifyCwdResolver`; runCmd calls it at spawn time (immediately before execFileCli) and passes the result as runCwd to resolveCommandCwd. Every orchestrate.ts call site that spawns post-merge or run-level verification passes integrationCwdResolver(integrationRoot, repoRoot); none passes a story worktree path. resolveCommandCwd keeps its existing sibling-remap behaviour, which now maps a stale story path onto the integration root.
2. Cleanup gating: src/execution/worktree.ts gains a reference count guarded by the same lock style as retention — `retainForVerification(agentId: string): () => void` returning a release function, and cleanupAll/cleanup skips (and logs, never throws) any worktree with a non-zero count, deferring removal to the release. The verification caller acquires the lease before spawning and releases it in a finally.
3. Missing cwd is environment: the verify.ts:1262-1269 branch keeps status "failed" and retryable:false but stamps the command result `environment: true` and a tail of the exact form `verification cwd missing: <path>`, and must not be counted as a test regression by the reporting path. STORY-170 turns that flag into its "environment" bucket.
**Consequences:** The resolver is optional so existing verifyBuild callers compile unchanged; only orchestrate.ts's post-merge and run-level sites are required to pass it. IntegrationWorktree.remove is unchanged — it already keeps __run on retention. STORY-170 must consume `environment: true` rather than re-detect a missing directory.
