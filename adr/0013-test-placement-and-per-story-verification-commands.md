# ADR-0013: Test placement and per-story verification commands

**Status:** Accepted
**Context:** Rust tests in this crate live in inline #[cfg(test)] modules in the file under test (run_registry.rs:250-308); TS tests live under packages/baro-orchestrator/test/<area>/<name>.test.ts and run with node:test. Repo-wide test commands are rejected by the shell, and each story may only verify its own perimeter.
**Decision:** Rust: every new test is an inline `#[cfg(test)] mod tests` in the file the story owns; no new files under crates/baro-tui/tests/. Story verification command: `cargo test -p baro-tui <module>::tests` (e.g. `cargo test -p baro-tui cli::run_registry::tests`, `cli::cli::tests`, `cli::launch::tests`, `executor::tests`). Never `cargo test` unscoped.
TS: node:test files at the paths listed in ADR-001, run as `node --import tsx --test packages/baro-orchestrator/test/<area>/<file>.test.ts` from the repo root, plus `npm run -w packages/baro-orchestrator typecheck` for stories that change TS types. Never `npm test -w packages/baro-orchestrator`.
No dependency is added or reinstalled in either stack. A targeted test that fails under machine load is re-run once in isolation and the isolated result decides.
**Consequences:** The run-level gate is the only place the whole tree is verified. Detached-process spawning and caffeinate spawning have no automated coverage; the PR description must state that gap explicitly, as ADR-004 requires.
