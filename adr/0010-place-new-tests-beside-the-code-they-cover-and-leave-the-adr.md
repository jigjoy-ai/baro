# ADR-0010: Place new tests beside the code they cover and leave the ADR-0007 dominance test untouched

**Status:** Accepted
**Context:** Tests run under `node --test` with `test/` mirroring `src/`; each existing timer fake is defined locally in its own test file rather than shared. ADR-0007 fixes three exact values in test/run-architect-outcome.test.ts:260-283 (decision 0ms / obligation 10_000ms, `--timeout-ms 2000`, regex /shared 2000ms phase budget/u) and explicitly forbids editing the tight-margin test at :285-329; it drives a real child process, so no fake clock reaches it.
**Decision:** New files: `test/runtime/awake-clock.test.ts` covering, through `createFakeAwakeClock()` only and with no real sleeping: (a) no gap — `awakeNow()` tracks wall exactly and `absorbedGapMs() === 0`; (b) one large gap — a single multi-hour `suspend()` is absorbed whole; (c) many small gaps — repeated `suspend()` calls each above threshold accumulate, and sub-threshold drift accumulates nothing; (d) a gap landing exactly on the deadline boundary — `suspend()` of precisely the remaining wall time does not expire the deadline, and a subsequent `advance()` of 1ms past it does.

Per-adopter regression tests, each proving both halves of the property (a simulated multi-hour suspension inside a 30-minute budget does NOT trip it; the same awake elapsed without suspension DOES): add to the existing files where one exists — `test/architect-openai.test.ts`, `test/execution/conductor.test.ts`, `test/execution/collective-board.test.ts`, `test/harness/exec-file-cli.test.ts` — and add new `test/verification/verification-goal-gate.test.ts` and `test/goal/goal-invariant-reviewer.test.ts` cases if no file exists. Each test constructs its subject with `awakeClock: createFakeAwakeClock()`; do not add a shared fake-clock helper module and do not rewrite `RecordingClock` (test/harness/exec-file-cli.test.ts:39-68) or `ManualClock` (test/harness/exec-file-cli-cpu-watchdog.test.ts:35-74).

Add the silent-extension test required by the acceptance criteria as `test/harness/exec-file-cli-awake-timeout.test.ts` and a gate case in the verification-gate file: after a suspend, the timeout must still fire at the original awake elapsed, proving the window was neither shortened nor lengthened.

Do NOT edit test/run-architect-outcome.test.ts:260-283 or :285-329, `writePhasedFakeCodex`, `writeSlowFakeHarness`, `runArchitect` or `runScript`. New script-level coverage for run-architect goes in a new file `test/run-architect-awake-budget.test.ts`.

Verification commands: `npm run typecheck` and `npm test` in packages/baro-orchestrator, plus `cargo test -p baro-tui` and `cargo build` at the repo root.
**Consequences:** ADR-0007's dominance-by-construction property and its `scripts/run-architect.ts`-unchanged spirit are respected in test architecture even though the script itself is edited by this goal: the dominance test's three pinned values and the `shared <N>ms phase budget` message template must not move, so the awake adoption in run-architect.ts has to keep that stderr text and its budget arithmetic shape byte-identical.
