# ADR-0003: Emit the warn activity once per prepareCriticEvaluation, not per prompt segment

**Status:** Accepted
**Context:** prepareCriticEvaluation (855-908) builds one prompt per AcceptanceContractSegment, so a naive emit inside the loop would produce N events for a segmented story; the criterion demands exactly one event per story with findings.
**Decision:** In `prepareCriticEvaluation(criteria, resultText, agentId, source?)`, call `altitudeEvidenceFor(agentId, source)` exactly once, before the segment loop, in parallel with the existing repository/command evidence collection where that is already awaited. Pass the resulting `section` as the 9th argument to every `buildEvalPrompt` call for every segment (identical advisory text in each segment). If `activity` is non-null, emit exactly one event, before returning: `emitActivity({ type: "activity", id: agentId, kind: "warn", text: activity })` — `id` is the story id (agentId is the story id at the wiring site, orchestrate.ts:1017-1018). If `activity` is null, emit nothing. Do not add any field to `CriticEvaluationPreparation`, do not add issues entries for altitude, and do not change the returned prompts' count or numbering.
**Consequences:** Segmented and non-segmented stories both produce exactly one warn line. Advisory text is duplicated across segments, which is intentional so each segment's critic sees it.
