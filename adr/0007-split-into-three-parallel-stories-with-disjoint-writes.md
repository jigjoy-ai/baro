# ADR-0007: Split into three parallel stories with disjoint writes

**Status:** Accepted
**Context:** The goal requires every story to declare exact repository-relative writes with no overlap across parallel stories, and each story to verify only its own perimeter. The work partitions cleanly into the Rust spawn path, the TS resume gate, and the Rust registry — three file sets that do not intersect.
**Decision:** Exactly three stories, writes as listed and non-overlapping:
- Story 1 — Resume flag on the orchestrator child argv (ADR-001, ADR-002). writes: ["crates/baro-tui/src/orchestrator_client.rs", "crates/baro-tui/src/main.rs"]. Verify: `cargo build -p baro-tui` and `cargo test -p baro-tui orchestrator_client::tests::`.
- Story 2 — cli.ts resume gate + helper + test (ADR-003, ADR-004). writes: ["packages/baro-orchestrator/src/runtime/resume-mode.ts", "packages/baro-orchestrator/scripts/cli.ts", "packages/baro-orchestrator/test/runtime/resume-mode.test.ts"]. Verify, from `packages/baro-orchestrator`: `npm run typecheck` and `node --import tsx --test test/runtime/resume-mode.test.ts`.
- Story 3 — Registry cleanup on stop (ADR-005, ADR-006). writes: ["crates/baro-tui/src/cli/run_registry.rs"]. Verify: `cargo build -p baro-tui` and `cargo test -p baro-tui run_registry::tests::`.
No story may write `crates/baro-tui/src/cli/launch.rs`, `crates/baro-tui/src/cli/detach.rs`, `packages/baro-orchestrator/src/orchestrate.ts`, or `packages/baro-orchestrator/src/execution/resume-selection.ts`. No story runs the repo-wide `npm test` or a bare `cargo test`. Dependencies are pre-installed; no `npm install` or `cargo fetch`.
**Consequences:** Stories 1 and 3 both build the same crate concurrently; cargo's lock serialises the builds, which may slow but not fail them. If a targeted test fails under load, rerun it once in isolation and let the isolated result decide. The run-level gate covers the merged tree once.
