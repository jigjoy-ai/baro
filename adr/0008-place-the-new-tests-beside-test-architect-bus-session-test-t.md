# ADR-0008: Place the new tests beside test/architect-bus-session.test.ts and copy its transport-faking pattern

**Status:** Accepted
**Context:** Four new behavioral assertions are needed (repair message contents, receipt ids, prose-then-JSON recovery inside the 3-attempt budget, composition-failure message) plus a stderr assertion. Existing planner/architect tests live flat in packages/baro-orchestrator/test/ with topical subdirectories (test/acceptance/, test/execution/); test/architect-bus-session.test.ts:187-229 already demonstrates byte-pinning a repair prompt and scripting a reject-then-fix reply sequence. adr/0013 governs test placement and per-story verification commands.
**Decision:** Add exactly two test files, no new subdirectory: packages/baro-orchestrator/test/planner-finalization-repair.test.ts (covering the repair message content including every unowned id and the `Expected schema:` block, the prose-then-corrected-JSON success within `maxFinalizationAttempts = 3`, and the empty-tail composition failure message listing the ids) and packages/baro-orchestrator/test/planner-progressive-obligation-note.test.ts (covering the receipt's `obligationNote` containing concrete ids, the `unownedObligationIds` array, and the `[planner-obligations] fragment … admitted; unowned N/M: …` stderr line per admission). Import the same test runner, assertion library and helper style as test/architect-bus-session.test.ts — do not introduce a different runner or add a test dependency. Fake the lane the way that file does: script the participant's replies so reply 1 is prose and reply 2 is valid final-PRD JSON, and capture prompts via the `sendUserMessage` spy. Stub `process.stderr.write` to capture announcement lines and restore it in teardown. Byte-pin the repair message's section labels (`Defects (`, `Unowned architecture obligations (`, `Expected schema:`, `Anything that is not that JSON object is discarded.`) rather than the whole string. Add regression assertions that `validateArchitectureObligationCoverage` still throws in `"complete"` mode with its existing message and that a parsed-but-rejected candidate still returns `fail("planner_failed", reason)` without composing. Run them with the package's existing test command from adr/0013; do not add a new npm script.
**Consequences:** Test discovery and CI need no configuration change. The two files split cleanly along the module boundary, so the planner-bus-session work and the planner-openai-progressive work can proceed in parallel with disjoint writes; the shared modules (obligation-coverage-report.ts, planner-prompts.ts, architecture-obligation-contract.ts) must land before either, since both depend on them.
