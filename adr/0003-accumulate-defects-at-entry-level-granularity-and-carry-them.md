# ADR-0003: Accumulate defects at entry-level granularity and carry them on the existing error classes

**Status:** Accepted
**Context:** Flavor A has ~35 throw sites across two files and flavor B throws inside parsePredicate; converting every inner throw to an accumulator is a large, risky rewrite that the goal does not require. Existing tests assert on the error CLASS and on message regexes (goal-constraint-appendix.test.ts:70-73, :84; architect-obligation-segments.test.ts:265-272), so a brand-new aggregate error class would break the 'still rejects exactly as before' criterion.
**Decision:** Keep the existing error classes as the thrown type; add defect carriage to them.
- Add `readonly defects: readonly ContractDefect[]` to `GoalConstraintContractError` (goal-constraint-appendix.ts:32-37) and to `ArchitectObligationSegmentError` (architect-obligation-segments.ts:126-131) and to `ArchitectOutcomeContractError` (architect-outcome.ts:104-109). Each constructor accepts an optional `defects` (via an options object member alongside the existing `cause`); when omitted it defaults to `[{ path: "", message }]`.
- The thrown `message` MUST equal `joinDefectMessages(defects)`. With exactly one defect this reproduces today's message character-for-character, so existing class assertions and message regexes keep passing.
- Accumulation happens ONLY at these loop boundaries; inner helpers keep throwing on their first violation:
  * `validateGoalConstraintPredicates`: the non-array check and the `length > MAX_CONSTRAINT_PREDICATES` check still throw immediately (fail-fast, unchanged). The per-entry map becomes a loop that wraps `parsePredicate(entry, index)` (and its preceding `normalizeRecordKeys`) in try/catch, records `{path: `constraintPredicates[${index}]`, message: <thrown message, with any duplicated `constraintPredicates[i]` prefix left exactly as parsePredicate wrote it>}`, continues to the next entry, and after the loop throws one `GoalConstraintContractError` carrying all defects if any were collected.
  * `parseSegmentResponse` (architect-obligation-segments.ts:395-400): top-level shape checks (:432-436) and the obligation-count bound (:442-450) still throw immediately. The per-draft loop wraps each draft's normalization + `exactRecord` + field validation + `validateDraftDecisionIds` + contract validation in try/catch, recording `{path: `obligations[${index}]`, message}` and continuing, then throws a single `ArchitectObligationSegmentError` with the full defect list. `ArchitectObligationOutputLimitError` is re-thrown immediately and never collected — it is a control-flow signal routed to bisection at :269-277.
  * `parseArchitectOutcome`: collects defects from `validateGoalConstraintPredicates` and from the per-entry loops over `evidence` and `questions`; all other checks keep their current fail-fast order.
- `ContractNormalizationError` thrown by `normalizeRecordKeys` is caught at the same loop boundary and recorded as a defect with the error's `path`; the ambiguity message is used verbatim.
- Defect order is source order (entry index ascending); no de-duplication, no re-ordering, no severity on defects.
**Consequences:** A validation failure now reports every bad entry in one pass while each entry still reports its own first problem — this is the exact meaning of 'enumerate every defect found in that attempt' for this codebase. No semantic check is relaxed: evidence-entry bounds (architecture-obligation-contract.ts:428-436) and kind/pathSuffix consistency (goal-constraint-appendix.ts:99-108, :119-123) are untouched code paths. Consumers that only read `.message` are unaffected.
