# ADR-0004: Carry the retry fields to the TUI wire through one exported mapper in tui-protocol.ts

**Status:** Accepted
**Context:** orchestrate.ts:1984-1989 rebuilds each command field-by-field and drops `retriedAfterFailure`/`firstFailureTail`; its target type tui-protocol.ts:44-49 declares only four keys, so adding keys inline would not typecheck. Nothing today asserts the emitted `done` payload, and driving `orchestrate()` end-to-end to produce a retried command is an expensive, flaky fixture. Rejected: asserting through `orchestrate()` with `emitTuiEvents: true`; rejected: a new module file, since tui-protocol.ts already owns the wire shape.
**Decision:** In `packages/baro-orchestrator/src/tui-protocol.ts`: extend the command element of `VerificationEvidenceInfo` (:44-49) with two optional snake_case keys — `retried_after_failure?: true` and `first_failure_tail?: string` — and export a pure mapper in the same file:
```ts
export function toVerificationEvidenceInfo(evidence: RunVerificationEvidence): VerificationEvidenceInfo
```
using a type-only import of `RunVerificationEvidence` from `./events/verification.js`. It returns `{ verification_id: evidence.verificationId, status: evidence.status, duration_ms: evidence.durationMs, commands: evidence.commands.map((command) => ({ command: command.command, status: command.status, duration_ms: command.durationMs, ...(command.tail ? { tail: command.tail } : {}), ...(command.retriedAfterFailure ? { retried_after_failure: true as const } : {}), ...(command.firstFailureTail !== undefined ? { first_failure_tail: command.firstFailureTail } : {}) })) }`. Conditional spreads only — never emit a key with an `undefined` value. Do not map `output` to the wire.
In `packages/baro-orchestrator/src/orchestrate.ts`: replace the inline object at :1980-1991 with `verification: toVerificationEvidenceInfo(summary.verification)` (keeping the existing `summary.verification` presence guard and every other key of the `done` event byte-identical). Import the mapper from `./tui-protocol.js` alongside the existing imports from that module.
Do NOT modify `crates/baro-tui/src/events.rs` or any Rust file: serde ignores unknown fields, so the new keys are backward-compatible and the Rust side is out of scope for this run.
**Consequences:** There is now exactly one owner of the camelCase→snake_case verification projection; future fields are added in one place. The Rust TUI keeps parsing today's payload unchanged and simply ignores the two new keys until someone adds them there (follow-up, not this run). `output` stays off the wire deliberately.
