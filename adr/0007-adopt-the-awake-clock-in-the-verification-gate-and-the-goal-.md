# ADR-0007: Adopt the awake clock in the verification gate and the goal-review deadline, and promote `createGoalReviewDeadline` to that module's shared owner

**Status:** Accepted
**Context:** verification-goal-gate.ts:75,127-154 arms one-shot NamedTimers watchdogs with no re-check — precisely the 'sleep silently extends a setTimeout' case the acceptance criteria call out. `createGoalReviewDeadline` (goal-invariant-reviewer.ts:790) is module-private with two in-file call sites while only the type `GoalInvariantReviewDeadline` is exported (goal-invariant-review-evidence.ts:26-31); duplicating an awake variant would give two owners.
**Decision:** src/verification/verification-goal-gate.ts: add `awakeClock?: AwakeClock` to the gate's construction options; keep the `NamedTimers<"verification" | "goalCompletion">` instance (:75) for handle bookkeeping, but arm each watchdog through `createAwakeDeadline({ budget: "verification-gate" | "goal-completion-gate", timeoutMs, onExpired, clock })`, and call `close()` where `this.timers.clear(...)` is called today (:154 and the sibling clear). The timeout must still fire at the same awake elapsed as today — assert this with a test rather than relying on the armed delay.

src/goal/goal-invariant-reviewer.ts: keep `createGoalReviewDeadline` in this file as the single owner (do NOT move it and do NOT create a second factory elsewhere), but change its signature to `function createGoalReviewDeadline(parentSignal: AbortSignal, timeoutMs: number, clock: AwakeClock = sharedAwakeClock()): ActiveGoalReviewDeadline`. Inside, keep `Math.max(1, timeoutMs)` (:794), the forked child AbortController and parent-abort propagation (:797-803), the idempotent `close()` and cleanup drain (:810-818) exactly as they are; replace only the `setTimeout` abort (:804-808) with `createAwakeDeadline({ budget: "goal-review", ... })` and set `deadlineAt = clock.awakeNow() + effectiveTimeoutMs` (:809). Both call sites (:320, :362) pass no clock unless injected from above. `GoalInvariantReviewDeadline.deadlineAt` (goal-invariant-review-evidence.ts:26-31) is henceforth an awake timestamp; every comparison against it in goal-invariant-review-evidence.ts (:58,:223,:247,:279,:397,:536,:663,:679,:697,:710,:717,:725,:791) and goal-invariant-reviewer.ts (:871,:909) must use the same clock — thread the clock alongside the deadline rather than calling `Date.now()`. `GOAL_REVIEW_STABLE_CAPTURE_BUDGET_MS` (goal-invariant-review-evidence.ts:24) keeps its value.
**Consequences:** The exported `GoalInvariantReviewDeadline` type is unchanged structurally, so no consumer signature breaks, but its `deadlineAt` time base changes; any future comparison against `Date.now()` there is a bug. The verification gate gains re-arm behaviour without changing its event payloads.
