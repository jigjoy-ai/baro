# ADR-0004: Announce the same gap on the host coordinator admission path

**Status:** Accepted
**Context:** planner-bus-session publishes through the event bus into the coordinator's private onPlanFragmentProposed (progressive-planning-coordinator.ts:260), and progressive-planner-protocol.ts:218-243 is a second in-host admission site. Both already call validateGoalContractCoverage in mode "partial" and both already emit obligation notes; without an announcement here the native lane can admit a fragment with a silent gap.
**Decision:** In packages/baro-orchestrator/src/planning/application/progressive-planning-coordinator.ts, after the successful admit in `onPlanFragmentProposed` (the path whose coverage check is at :356-360), compute `unownedInvariantIds(goalContract, <all admitted stories after this admission>)` using the mapping-free helper from ADR-001 and, when `totalInvariants > 0 && unowned.length > 0`, call `emitInvariantCoverageGap({ fragmentId, unownedInvariantIds: unowned, totalInvariants })`. Extend the `admitted` variant of `PlanFragmentAdmissionOutcome` (:103-107) with the OPTIONAL field `readonly unownedInvariantIds?: readonly string[]` and populate it; do not change the `replayed` or `rejected` variants. Apply the identical announcement in packages/baro-orchestrator/src/planning/application/progressive-planner-protocol.ts after `this.planSession.admit(candidate)` (:243). Reuse the coordinator's existing goal contract handle; do NOT re-derive it from the envelope in a second place if one is already in scope. Do NOT touch the final-PRD reconcile mode at :590-598 (it stays `"partial"`).
**Consequences:** Optional outcome field keeps existing destructuring callers compiling. The gap can be announced twice for the bus lane (once in the publisher, once in the coordinator); duplication is acceptable and preferable to a silent lane — tests must assert at-least-once, never exactly-once.
