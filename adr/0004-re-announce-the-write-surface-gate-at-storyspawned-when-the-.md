# ADR-0004: Re-announce the write-surface gate at StorySpawned when the surface key changed since WorkLeaseGranted

**Status:** Accepted
**Context:** `announceRevisedSurfaces` runs only on RuntimeReplanApplied (collective-board.ts:3279), so a replan landing in the window between WorkLeaseGranted and StorySpawned leaves the spawned worker holding the surface it was offered. The board has no StorySpawned case today (only StorySpawnFailed at 671-674), and the lease record already carries `announcedSurfaceKey` (2486) as the comparison anchor. Re-announcing unconditionally at spawn would violate the 'no extra announcement when nothing changed' criterion; announcing from the story factory would duplicate lease state the board owns.
**Decision:** In packages/baro-orchestrator/src/execution/collective-board.ts only:
1. Extract the per-lease body of `announceRevisedSurfaces` (3288-3311) into a private method `announceSurfaceRevision(storyId: string, lease: <existing lease record type>, graphVersion: number): void` that: looks the story up in `this.prd.userStories` and returns if absent; computes `surface = storyWriteSurface(story, this.prd.userStories)` and `key = surfaceKey(surface)`; returns if `key === lease.announcedSurfaceKey`; assigns `lease.announcedSurfaceKey = key`; returns if `surface === undefined`; otherwise emits GateRuleAnnounced with `{runId: this.runId, storyId, leaseId: lease.leaseId, generation: lease.generation, gateId: "write-surface", graphVersion, surface}`. `announceRevisedSurfaces(graphVersion)` becomes a loop over `this.leases` delegating to it. Behaviour for the replan path must be byte-identical to today.
2. Add a `StorySpawned` case to the board's semantic-event dispatch switch, next to the existing `StorySpawnFailed` case (671-674), with the same runId gating the neighbouring cases use, calling a new private `onStorySpawned(data)`.
3. `onStorySpawned` resolves `lease = this.leases.get(data.storyId)`; returns if there is no lease; otherwise calls `announceSurfaceRevision(data.storyId, lease, <the board's current graph version>)` — the same field/value the board passes as `graphVersion` when it emits RuntimeReplanApplied at 3264-3280. `leaseId` and `generation` on the emitted event MUST come from the stored lease record, never from the spawn event, so story-agent.ts:410-422 matching keeps working.
Do NOT change src/market/story-factory.ts, src/events/execution.ts, or the story agent. Do NOT add new fields to GateRuleAnnouncedData or to the lease record.
**Consequences:** Because `announcedSurfaceKey` was seeded from the grant's surface at lease time, a spawn with no intervening graph change produces no event (early return at the key comparison), and a spawn after a surface-changing replan produces exactly one announcement carrying the current graph version. If the replan path already announced in that window, the key is already stored and spawn stays silent — announcements remain at-most-once per distinct key per lease. A board test must cover both branches.
