# ADR-0004: Place new tests as node:test files using the existing stdout monkey-patch convention, with no subprocess spawning

**Status:** Accepted
**Context:** The package runs node:test through tsx (package.json:15); there is no vitest and no test config. test/tui-protocol.test.ts:6-21 already swaps process.stdout.write and restores it in finally, and process.stdout is an EventEmitter, so backpressure can be simulated in-process without any injected-stream seam. tsconfig includes only src, so test files are not typechecked and must not be relied on for type coverage.
**Decision:** Two test files, owned by disjoint stories:

A) Extend packages/baro-orchestrator/test/tui-protocol.test.ts (append a new `describe` block; do not rewrite the existing captureEmit tests). Import `{ emit, flushTuiProtocol, flushTuiProtocolWithTimeout, resetTuiProtocolFlushState }` from "../src/tui-protocol.js". Backpressure fake: stub `process.stdout.write` with a function returning `false` (cast as `typeof process.stdout.write`, matching tui-protocol.test.ts:6-21), restore in finally, and release with `process.stdout.emit("drain")`. Required cases:
1. immediate-resolve: with write returning true, `flushTuiProtocol()` resolves without any drain (assert via `Promise.race` against a resolved sentinel, not a wall-clock timer).
2. drain-gated: after an emit whose write returned false, the flush promise is still unresolved (race against a `queueMicrotask`/`setImmediate` sentinel), then resolves after `process.stdout.emit("drain")`.
3. emit-after-flush-started: emit (false) → start flush → emit again (false) → single `drain` resolves the outstanding flush; assert only one 'drain' listener was registered (`process.stdout.listenerCount("drain")` ≤ 1 while pending).
4. flushTuiProtocolWithTimeout returns "timeout" for an injected never-resolving flush with a short timeoutMs (e.g. 10) and "flushed" for an injected resolved flush — this is the cli.ts stand-in coverage.
Every case must call `resetTuiProtocolFlushState()` in finally. No child_process, no spawn, no real git.

B) New file packages/baro-orchestrator/test/orchestrate-run-diff-cap.test.ts (top level of test/, alongside collective-orchestrate.test.ts). Import `{ capRunDiff, MAX_RUN_DIFF_BYTES }` from "../src/integration/run-diff-cap.js". Required cases: under-cap string returned strictly equal (`assert.equal`) to input; undefined → undefined; over-cap input (built from repeated newline-terminated lines) whose result has `Buffer.byteLength(result) <= MAX_RUN_DIFF_BYTES + marker length`, ends with the exact marker `… (run diff truncated: <n> bytes omitted)`, has its last pre-marker character `\n`, and whose reported `<n>` equals input bytes minus kept bytes; a single-huge-line input with no newline in the first MAX_RUN_DIFF_BYTES bytes yields marker-only output.

Both files use `describe`/`it` from node:test and `node:assert/strict`. Targeted runs from repo root: `node --import tsx --test packages/baro-orchestrator/test/tui-protocol.test.ts` and `node --import tsx --test packages/baro-orchestrator/test/orchestrate-run-diff-cap.test.ts`. Do not add a test runner, config file, or dependency; dependencies are already installed at the root.
**Consequences:** Both suites run in-process in milliseconds and stay in the fast lane (scripts/test-lanes.mjs SLOW_PATTERNS does not match either name — verify the new file name does not match a slow pattern before finalizing). Because tests are not typechecked, any type error in the new src exports will surface via `npm run typecheck` on src only.
