# ADR-0006: Record the diagnosis in `docs/resume-fail-closed-diagnosis.md` and copy it into the PR description

**Status:** Accepted
**Context:** The acceptance criteria require the PR description to name the exact diagnosed divergence point with differential evidence from run-22657 (good) and run-18904 (bad). Implementation agents cannot author a PR body directly, and the two run artifacts were not confirmed present in this checkout, so fabricated log quotes are a real risk.
**Decision:** Create `docs/resume-fail-closed-diagnosis.md`, owned by exactly one story, containing: (1) the divergence point stated as file:line — `crates/baro-tui/src/main.rs:429-431` collapsing an unreadable/unparseable prd.json to `None`, and the three unguarded exits at main.rs:1215, main.rs:1225 (no `else`), main.rs:1276 (`Err(_) => {}`); (2) a differential section comparing run-22657 (good) and run-18904 (bad) that states, for each, which of those branches was taken and the resulting observed behaviour; (3) the two honest exits (`--continue`, delete prd.json) verbatim from `RESUME_EXITS`; (4) an explicit note that the architect obligation-coverage brittleness that felled the fresh plan in run-18904 is a known separate defect and out of scope. Evidence must be cited only as it can be substantiated: if the run logs are not in this checkout, cite the runs by id and their observed outcome and label the code-level divergence as the substantiated part — do not invent log lines or file paths. The PR description reproduces this file's content; no other doc, README, CHANGELOG or adr/ file is edited by this goal.
**Consequences:** The diagnosis is a single-file write that cannot collide with the code stories and can run in parallel with them. `adr/` numbering and `CHANGELOG.md` stay untouched, so no story needs to coordinate on the next ADR number.
