# ADR-0002: Pass the advisory section into buildEvalPrompt as a new trailing optional parameter

**Status:** Accepted
**Context:** The advisory text must appear in the evidence prompt as its own "## Altitude findings (advisory)" section. Appending it to the repositoryEvidence string was rejected: that string is passed through redactSensitiveText + boundText and can be truncated, which would silently drop or mangle the section. buildEvalPrompt is positional (975-984) and is also re-exported by src/harness/claude/critic.ts:44, so the parameter must be optional and last.
**Decision:** Change the signature to `export function buildEvalPrompt(criteria: readonly string[], resultText: string, commandEvidence: string | null = null, repositoryEvidence: string | null = null, decisionDocument: string | null = null, segment?: AcceptanceContractSegment, publishedNotes: readonly string[] = [], hostRunsWholeTreeVerification = false, altitudeSection: string | null = null): string`. When `altitudeSection` is a non-empty string, append it verbatim as its own section — Baro-generated trusted text, so do NOT pass it through redactSensitiveText and do NOT boundText it — positioned immediately AFTER the `## Baro-captured repository evidence` section and BEFORE `## Baro-captured run artifacts this story published`. When it is null/empty, emit nothing (no header, no blank marker). The section still counts toward CRITIC_MAX_PROMPT_CHARS in the existing length check at 1061-1065; keep that check unchanged. Do not add any other parameter, and do not reorder existing sections or rename existing headers.
**Consequences:** Existing callers and the claude re-export keep compiling unchanged. Existing section-ordering tests (test/acceptance/critic-evidence.test.ts:233-278, 280-306, 334-404) use relative indexOf comparisons and stay green because insertion is between two already-ordered sections.
