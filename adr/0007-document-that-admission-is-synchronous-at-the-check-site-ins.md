# ADR-0007: Document that admission is synchronous at the check site instead of awaiting an admission event

**Status:** Accepted
**Context:** Scouted trace proves the proposal->visibility path is synchronous: `admitGraph` -> `decide` -> synchronous persist -> `this.prd = outcome.applied.prd` (collective-board.ts:513-515) all complete before `onPlanFragmentProposed` returns; the only queue (`serialized-observer.ts:191-201`) is upstream of the entry point. Introducing an await/event-wait would add async surface for no correctness gain and would risk deadlock in the in-process test harness.
**Decision:** Do not make the tail path async and do not add any listener/promise for accept/reject. Add exactly one comment of at most three lines immediately above the `onPlanFragmentProposed` call in the tail block stating the non-obvious constraint and its proof, e.g.: `// Admission is synchronous: admitGraph -> RuntimeReplanCoordinator.decide persists and swaps board.prd before returning (collective-board.ts:498-517), so the returned outcome is authoritative and no accept/reject event needs awaiting.` Per the repo comment style, add no other narration comments in this change.
**Consequences:** Satisfies the acceptance criterion via the documentation branch. The correctness of the tail decision no longer relies on this property anyway, since the outcome is now returned directly.
