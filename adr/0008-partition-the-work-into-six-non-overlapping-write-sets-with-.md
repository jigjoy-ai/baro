# ADR-0008: Partition the work into six non-overlapping write sets with per-file test commands

**Status:** Accepted
**Context:** The goal requires each story to declare exact repository-relative writes with no overlap across parallel stories, and to verify only its own perimeter. The consumer graph (scout Q6) shows the shared module is a leaf everyone depends on, so ordering matters.
**Decision:** Exactly six stories; the `writes` arrays below are exhaustive and mutually disjoint. All test commands run from `packages/baro-orchestrator/`. Dependencies are already installed — no npm/cargo install steps.
- S1 (must land first): writes `packages/baro-orchestrator/src/contract/contract-normalization.ts`, `packages/baro-orchestrator/test/contract/contract-normalization.test.ts`. Verify: `node --import tsx --test test/contract/contract-normalization.test.ts`. Covers canonicalization, stripping notes, and the ambiguity rejection at unit level.
- S2 (after S1): writes `packages/baro-orchestrator/src/goal/goal-constraint-appendix.ts`, `packages/baro-orchestrator/test/goal/goal-constraint-appendix.test.ts`. Verify: `node --import tsx --test test/goal/goal-constraint-appendix.test.ts`. Owns the skipped-absent-entry test and the extra-field/casing tests for predicates.
- S3 (after S1, parallel with S2): writes `packages/baro-orchestrator/src/planning/domain/architect-obligation-segments.ts`, `packages/baro-orchestrator/test/planning/domain/architect-obligation-segments.test.ts`. Verify: `node --import tsx --test test/planning/domain/architect-obligation-segments.test.ts test/planning/domain/architecture-obligation-contract.test.ts`. Owns the obligation-flavor extra-field, canonicalization, ambiguity, and still-rejects tests.
- S4 (after S1 and S2): writes `packages/baro-orchestrator/src/planning/domain/architect-outcome.ts`, `packages/baro-orchestrator/test/architect-outcome.test.ts`. Verify: `node --import tsx --test test/architect-outcome.test.ts`.
- S5 (after S4): writes `packages/baro-orchestrator/src/planning/adapters/architect-bus-session.ts`, `packages/baro-orchestrator/test/architect-bus-session.test.ts` (NEW file at the test root, matching test/architect-outcome.test.ts and test/architect-openai.test.ts placement). Verify: `node --import tsx --test test/architect-bus-session.test.ts`. Owns the full-defect repair-prompt test and the budget-exhaustion message test, driven by an injected `validateOutcome` stub plus scripted replies — no network, no real model.
- S6 (last): writes `packages/baro-orchestrator/scripts/run-architect.ts`. Wiring only: pass the stderr note sink and `ARCHITECT_OUTCOME_SCHEMA_SUMMARY`. Verify: `node --import tsx --test test/architect-openai.test.ts`.
Nobody writes packages/baro-orchestrator/src/planning/domain/architect-prompts.ts, planner-prompts.ts, architecture-obligation-contract.ts, src/goal/goal-precondition-report.ts, src/orchestrate.ts, or anything under crates/. New tests follow the existing house style: `import assert from "node:assert/strict"`, `import { describe, it } from "node:test"`, relative source imports with a `.js` extension, in-file fixture consts/factories, no mocking library, and a comment above each case naming the drift it pins.
**Consequences:** S1 is a hard prerequisite; S2/S3 can run in parallel once it lands, and S5 needs S4's exported schema summary. No story runs `npm test`, `npm run test:fast` or `cargo test` — the run-level gate after integration owns the full suite. Because each story owns both its source file and its test file, no two agents can collide on a file.
