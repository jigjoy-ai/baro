# ADR-0007: Place new tests as node:test files mirroring src, verified per-file, and ship with "Fixes #107"

**Status:** Accepted
**Context:** The repo has no lint/format tooling and no runner config; per-file verification commands are the documented convention (adr/0008:4-13, adr/0013:6) and repo-wide suite commands are refused by gate-registry.ts:171-176. `test/` is not typechecked (tsconfig.json:15).
**Decision:** New test files, each `node:test` + `node:assert/strict`, no new dependency, no runner config:
- `packages/baro-orchestrator/test/harness/process-cpu-activity.test.ts` — sums a tree via an injected `ProcessCpuTableReader`; `null` table ⇒ `observed:false` and `cpuAdvanced` ⇒ true; delta below/above `CPU_ADVANCE_MIN_DELTA_MS`.
- `packages/baro-orchestrator/test/harness/exec-file-cli-cpu-watchdog.test.ts` — with a small `idleTimeoutMs` and an injected `cpuActivityProbe`: a silent-but-active process survives past the window; a silent-and-idle process is killed with the `presumed hung` message; the absolute `timeout` kills with the `exceeded the absolute limit` message.
- `packages/baro-orchestrator/test/verification/verify-run-level-retry.test.ts` — a run-level command failing once then passing yields a passing result with `retriedAfterFailure: true` and exactly one captured `emitActivity` event of `kind:"warn"` whose text contains the label, the first failure tail, and the retry; failing twice fails the gate with no third attempt; a spec with `origin:"declared"` is attempted exactly once and emits nothing.
Worktree residue/reuse coverage goes into the existing `test/integration/worktree.test.ts`.

Verification commands (run from the package): `cd packages/baro-orchestrator && node --import tsx --test test/harness/process-cpu-activity.test.ts test/harness/exec-file-cli-cpu-watchdog.test.ts`, `cd packages/baro-orchestrator && node --import tsx --test test/verification/verify-run-level-retry.test.ts`, `cd packages/baro-orchestrator && node --import tsx --test test/integration/worktree.test.ts test/integration/repository-command.test.ts`. Never `npm test`, never a repo-wide glob, never `--test-concurrency` in a per-story command. Comments stay lean per AGENTS.md. The commit/PR body must contain the literal line `Fixes #107`.
**Consequences:** Every acceptance criterion has a named owning test file and a runnable per-file command. Because `test/` is not typechecked, type errors in fixtures only surface at runtime — helpers must stay simple. No lint step exists, so style is enforced only by review.
