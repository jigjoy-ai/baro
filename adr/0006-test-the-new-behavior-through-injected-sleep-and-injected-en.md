# ADR-0006: Test the new behavior through injected sleep and injected env, never through real waits or process.env mutation

**Status:** Accepted
**Context:** test/harness/transient-retry.test.ts currently scrapes waits from the notice regex `/retrying in (\d+)ms/u` and sleeps real seconds; adding 4-attempt cases at the new ladder would add ~3 minutes to the slow lane. supervisor.test.ts already drives an injected `let now = 0` clock (:123-199).
**Decision:** Story A adds to `packages/baro-orchestrator/test/harness/transient-retry.test.ts` (node:test describe/it, matching the file's existing style), each case injecting `sleep: async (ms) => { waits.push(ms) }` so no test sleeps:
1. capacity failure retries to the policy attempt count with growing waits — a run() always throwing a provider_capacity-classified error under `resolveDialogueRetryPolicy({})`; assert run() was called 4 times and `waits` equals `[15_000, 45_000, 120_000]`.
2. a provider-supplied retry-after is still the base and still capped — retryAfterMs 30_000 → waits `[30_000, 90_000, 120_000]`.
3. deterministic failure fails on attempt 1 — an unclassified/infrastructure error with the same policy; assert run() called exactly once and `waits` is empty.
4. env overrides honored — `resolveDialogueRetryPolicy({ BARO_DIALOGUE_RETRY_ATTEMPTS: "2", BARO_DIALOGUE_RETRY_MAX_WAIT_MS: "20000" })` yields maxAttempts 2 / maxWaitMs 20_000 and the wrapper then produces exactly one wait of 15_000; plus a clamp/garbage case (`"abc"`, `"0"`, `"999"`) falling back or clamping per ADR-002. Pass the env as an explicit object literal; never mutate process.env.
5. existing tests in this file stay unchanged.
Story B adds to `packages/baro-orchestrator/test/execution/supervisor.test.ts` (flat node:test `test()` style, injected `now`), each constructing the supervisor with an explicit small `noProgressShellCalls`:
6. shell-only loop below the threshold → zero interventions;
7. exceeding the threshold → exactly one intervention whose reason matches `/shell commands with no file change/u`;
8. a file-mutation call (e.g. `write_file`) mid-loop resets the counter so a following sub-threshold shell run does not intervene;
9. the test at :47-66 must remain textually unchanged.
**Consequences:** Both new suites run in well under a second, so the slow-lane placement of test/harness/ costs nothing extra. Tests assert exact millisecond ladders, which locks ADR-002's constants: changing 15_000/120_000/4 later requires updating this one test file.
