# ADR-0006: Announce the per-admission coverage gap on stderr with a [planner-obligations] prefix, not on the plan_fragment wire record

**Status:** Accepted
**Context:** The goal wants the gap visible on each fragment admission. The stdout `plan_fragment` record cannot carry it without also editing `validateFragmentWireEvent` (progressive-planner-protocol.ts:337-365, which rebuilds fields and drops extras), the `BaroCommand` variant in tui-protocol.ts:299-306, and the typed Rust enum in planner_stream_bridge.rs:15-54/128-130 that re-serializes and strips unknown fields — a cross-stack protocol change well beyond the goal, with a TUI that has no fragment event variant to render it (crates/baro-tui/src/progressive_planning.rs:34). planner-bus-session.ts already uses stderr for exactly this kind of run-visible announcement (:542-544, :590-592).
**Decision:** In planner-openai-progressive.ts, immediately after computing `unowned`/`totalObligations` and before returning the receipt, emit exactly one line when `totalObligations > 0`: `process.stderr.write(`[planner-obligations] fragment ${fragmentId} admitted; unowned ${obligationGapSummary(unowned, totalObligations)}\n`)`. Use the `[planner-obligations]` prefix for every line this goal adds on that channel. Emit nothing when there is no obligation contract. Do NOT modify progressive-planner-protocol.ts, tui-protocol.ts, src/events/planning.ts (`PlanFragmentAdmittedData` keeps its current fields), the ReceiptObserver mapping in planner-bus-session.ts:137-151, or anything under crates/. Do not add a `deny_unknown_fields`-relevant field anywhere in Rust.
**Consequences:** Zero protocol/Rust risk and no schema migration; the gap is visible in run logs per admission and in the receipt per publish. The TUI still shows nothing about obligations — an acknowledged follow-up, not part of this goal. Tests capture the line by stubbing `process.stderr.write`, the same technique any existing test of the `[planner-bus]` lines uses.
