# ADR-0005: Canonicalize drifted `[G-…]` acceptance claims host-side and fold claimed ids into goalInvariantIds

**Status:** Accepted
**Context:** Stories claim invariants by id array only; GoalGuardian already writes `[G-A1] <text>` acceptance strings that nothing reads back. The goal requires drifted wording to be restored to the canonical statement with an announced warn while unknown ids and compound claims stay hard rejections. The obligation twin (canonicalObligationAcceptance, byte-exact compare, verbatim pass-through for the validator to reject) is the pattern to copy.
**Decision:** Create packages/baro-orchestrator/src/planning/domain/goal-invariant-canonicalization.ts exporting:
- `const INVARIANT_CRITERION_CLAIM = /\[(G-[^\]]+)\]/u` (unanchored, mirrors architecture-obligation-contract.ts:25) and `const INVARIANT_ID = /^G-[AC][1-9]\d*$/u`.
- `export function renderGoalInvariantCriterion(invariant: GoalInvariant): string` → `` `[${invariant.id}] ${invariant.text}` ``.
- `export type GoalInvariantNoteKind = "canonicalized_invariant_criterion"`; `export interface GoalInvariantNote { readonly severity: "warn"; readonly kind: GoalInvariantNoteKind; readonly storyId: string; readonly invariantId: string; readonly detail: string }`; `export type GoalInvariantNoteSink = (note: GoalInvariantNote) => void`.
- `export function canonicalInvariantAcceptance(contract: GoalContract | null | undefined, storyId: string, acceptance: readonly string[], onNote?: GoalInvariantNoteSink): { acceptance: string[]; invariantIds: string[]; changed: boolean }`.
Rules, per criterion: no `[G-…]` match → push verbatim. Match → split the captured text on `/[\s/,+&]+/u`; if the split yields exactly one part matching INVARIANT_ID AND that id exists in the contract, push `renderGoalInvariantCriterion(invariant)` and record the id; when the rendered text differs from the original by byte-exact `!==`, set `changed = true` and emit the note with detail `` `story ${storyId}: canonicalized paraphrased goal invariant ${invariantId} criterion text` ``, de-duplicated on key `` `${storyId} ${invariantId} ${kind}` ``. Otherwise (unknown id, compound claim, malformed token) push the criterion VERBATIM and record the raw trimmed capture as a claimed id so the existing validators reject it — never repair it, never drop it.
Fold sites (claimed ids are unioned into the story's goalInvariantIds, preserving existing order then appending new ids in first-appearance order, deduped):
- planner-validation.ts: run beside the obligation canonicalization at :111-119 and set `story.acceptance` / `story.goalInvariantIds` in place BEFORE the existing id-syntax loop at :121-137 and before the duplicate check at :138-142, setting `prdRepaired` so :199 re-serializes.
- progressive-planner-protocol.ts:201-217 and progressive-planning-coordinator.ts:318-331: fold by object spread into the candidate/repaired story, never in place, before their coverage validation.
Concrete sink: add `export function emitGoalInvariantNote(note: GoalInvariantNote): void` to plan-events.ts forwarding `note.detail` to `emitPlanActivity("warn", note.detail)`; pass it as `onNote` at all three fold sites. Do NOT extend `ObligationNoteKind` and do NOT reuse `ObligationNote` with the invariant id in `obligationId`.
Rejections stay where they are: unknown/malformed ids reach `"final PRD story ${id} contains an invalid goalInvariantIds entry"` (planner-validation.ts:121-137) or `GoalContractCoverageError("unknown_invariant")`; duplicate-owner claims mean the EXISTING intra-story duplicate rule at planner-validation.ts:138-142 — do NOT add any new cross-story or cross-fragment duplicate-ownership rejection, because GoalGuardian legitimately maps additional stories to an already-owned invariant.
**Consequences:** Folding makes acceptance-text claims count as ownership, so the ADR-001 gap shrinks accordingly. Byte-exact drift detection means canonicalization is idempotent and never argues about paraphrase similarity. Compound claims fail with the existing invalid-entry message rather than a new code.
