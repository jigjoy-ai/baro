# ADR-0001: Close the claude-lane receipt/warn gap at the shared publisher, never by duplicating note text in planner-bus-session.ts

**Status:** Accepted
**Context:** The goal asks that the claude lane (planner-bus-session.ts) produce the same invariantNote receipt and warn/stderr notice as the two progressive adapters. Research shows there is already exactly one construction site (planner-openai-progressive.ts:332-375) which the bus lane transitively reaches through createPlannerHarnessProgressiveSupport (planner-harness-progressive.ts:140). Re-implementing the note or the warn text inside planner-bus-session.ts would create the second dialect the goal forbids. The alternative — copying the block into the bus session — is rejected for that reason.
**Decision:** The implementing agent MUST first characterize the claude lane with a test (see the test ADR) rather than assume code is missing.
- Single owner: the invariantNote string, the `[planner-invariants] fragment <id> admitted; unowned …` stderr line, and the `onInvariantCoverageGap` warn call stay owned exclusively by `publish()` in packages/baro-orchestrator/src/planning/adapters/planner-openai-progressive.ts. Do NOT add the literals `WARNING:`, `[planner-invariants]`, `invariantNote`, or a new gap computation to planner-bus-session.ts.
- Whatever the characterization test proves missing on the bus lane MUST be fixed by (a) forwarding config through packages/baro-orchestrator/src/planning/adapters/planner-harness-progressive.ts to `createPlannerProgressivePublisher(config)`, and/or (b) making planner-bus-session.ts supply the missing input in its config object at :352-389, using ONLY the existing key names `onInvariantCoverageGap` (type `InvariantCoverageGapSink` from ../application/plan-events.js) and `trustedGoalEnvelope`.
- Do NOT change the note text, the stderr text, the warn text, the gap gating conditions (`totalInvariants > 0` for stderr; `totalInvariants > 0 && unowned.length > 0` for note and warn), or `formatInvariantIdList`/`invariantGapSummary`/`unownedInvariantIds` signatures.
- If the characterization test passes unchanged, the correct outcome for this part is the test plus no production edit; record that in the PR body. Do not invent a refactor to create a diff.
**Consequences:** Both lanes remain byte-identical by construction, so a text change is a one-file change forever. Agents must run the characterization test before editing adapters; a production diff that is not demanded by a failing test is out of scope for this run.
