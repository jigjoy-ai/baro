# ADR-0010: State the run-19681 board-side diagnosis, with eliminated candidates, in the PR description

**Status:** Accepted
**Context:** Acceptance requires the PR to name which board-side validation actually rejected the fragment, diagnosed from code. Scouted enumeration eliminates one of the three user-supplied candidates outright.
**Decision:** The PR description must contain a `## run-19681 diagnosis` section that: (a) names the rejecting validation with file:line and the exact reason string it produces; (b) explicitly records that the 'declared `writes` overlap with already-merged stories' candidate is eliminated — no writes-overlap validation exists on the fragment-admission path (`runtime-replan-coordinator.decide` gates: proposal_id_conflict :145, run_not_active :151-157, invalid_proposal :163-172, inactive_source :184, stale_graph_version :192, adaptation_budget_exhausted :205, prompt_projection_overflow :245, persistence_failed :301; `validateRuntimeReplanMutation` gates: duplicate_story `src/runtime/runtime-replan.ts:158-161`, unknown_story :167); (c) discriminates the two surviving candidates by the reason string each emits — lifecycle/wave gating surfaces as `planning_not_open` (`progressive-planning-coordinator.ts:240-249` / `:385-391`) or `graph_rejected: runtime graph adaptation is only available while the collective run is active` (`runtime-replan-coordinator.ts:151-157`), while obligation-restatement hardening surfaces as `invalid_fragment` from `validateArchitectureObligationCoverage` (`architecture-obligation-contract.ts:293-308`) and story re-proposal surfaces as `graph_rejected: cannot add existing story '<id>'`; (d) states which of these the run-19681 evidence matches, or, if the run's recorded reason is unavailable in this checkout, says so explicitly and names the single most likely gate with its citation instead of asserting an unverified one.
**Consequences:** The PR text is a deliverable of this change, not optional. The propagated reason introduced by this work makes the same diagnosis mechanical for future runs.
