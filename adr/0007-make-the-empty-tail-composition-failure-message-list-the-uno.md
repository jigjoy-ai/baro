# ADR-0007: Make the empty-tail composition failure message list the unowned ids and state the success condition

**Status:** Accepted
**Context:** The composition failure at planner-bus-session.ts:569-592 returns `${reason}; host empty-tail composition also failed: ${composeError.message}`, which repeats the coverage string but tells an operator nothing about what would have made it succeed. The guard itself must stay fail-closed: a candidate that parsed and was rejected still short-circuits to `fail`, and composition is attempted only for shapeless prose with an early plan.
**Decision:** Keep planner-bus-session.ts:556-592 structurally identical — same `closeStdin()`, same `candidate !== null || !progressive.hasEarlyPlan()` short-circuit, same empty-`userStories` composition through `progressive.reconcileFinalCandidate`, same `fail("planner_failed", ...)` return on catch, same lean comment block (do not expand it into an essay). Change only the catch-branch message to: `` `${reason}; host empty-tail composition also failed: ${detail}` `` — where `detail` is the compose error message as today — with, appended only when the id list resolved for this rejection is non-empty, `` `; unowned architecture obligations (${n}): ${formatObligationIdList(ids)}; composition would have succeeded only if a story published before the tail had claimed each of these ids in its acceptance text — published stories are immutable, so this cannot be repaired after the fact` ``. Resolve `ids` as `missingObligationIdsFromError(composeError)` falling back to `progressive.unownedObligationIds()`. When the list is empty, append nothing. Do NOT change the returned code (`"planner_failed"`), the `fail` helper, or the success-path stderr line at :590-592.
**Consequences:** Fail-closed behavior is byte-for-byte preserved; only the diagnostic string grows. The message can get long with many obligations, bounded at 40 ids by `formatObligationIdList`. Any existing test asserting the exact composition-failure string must be updated to a substring assertion.
